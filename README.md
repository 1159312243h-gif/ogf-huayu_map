# 华域地图

**当前项目版本：7.0**

当前构建：`7.0-huayu-terrain-camera-v1`（7.0.0，2026-10-12）。透视地形从现有等高线材质网格生成同源高程与材质瓦片，道路、水体、园林与模型共用贴地表面；恢复俯视时复用原材质和缓存。行政区、下级区划、地点、道路及下载范围高亮改为跟随实际相机，修复缩放、拖拽、侧栏切换和透视恢复俯视后的轮廓错位。

继续包含模拟卫星底图、花园模型、标准及深夜底图的地市边界层级和交通增量显示。全图按铁路、地铁、有轨电车及公交系统分别设站，保留原始站名、完整线路详情及北沪、筑湾换乘规则；津川铁路站与地铁津川火车站分别显示。下载图片保留 1200、2400、4800 像素长边选项及对应 TIF 配准。山地高程高度场、完整地形快照、模型持久缓存和已确认渲染规则继续应用；交通与地形由 GitHub Actions 每三小时更新，页面每五分钟检查新版。

[在线访问华域地图](https://ogf-atlas.pages.dev/)

华域地图是基于 [OpenGeofiction](https://opengeofiction.net/)（OGF）数据构建的中文地图应用。项目不仅包含可直接部署的网站，还包括华域标准与深夜样式、交通数据快照、导航逻辑、实时三维建筑服务、版本归档、校验脚本、自动部署流程和中文运维文档。

项目目标是在保留 OGF 数据开放性和持续更新能力的基础上，提供更完整的中文地图表达：从国家和行政区到城市街道、公共交通、建筑、城墙、花园和各类公共设施，都按照统一的视觉与交互规则呈现。

## 主要功能

### 华域地图样式

- **华域标准**：默认基础图层，针对道路、行政边界、地名、水体、土地利用和各类设施重新设计。
- **华域深夜**：为夜间浏览提供独立的深色配色，保留道路、交通和土地利用层级。
- **华域模拟卫星**：可在底图菜单选择，根据 OGF 地物生成俯拍屋顶、树冠及林地、农田等自然材质，加入地表斑驳、屋顶纹理和平面投影，非实拍卫星影像。默认隐藏密集地名和图标，可勾选“影像注记”恢复地名；行政边界与地下线路不作为影像内容绘制。此模式不显示三维模型侧壁、柱子、树干或立体花簇，保持俯视；切回标准或深夜地图恢复原有模型。复用现有地形与模型快照，交通和地形仍可分别叠加。
- **官方底图对照**：OGF-Carto、Topo、CyclOGF、6ma 和官方 Vector 仍可按需切换。
- **多级标签与边界**：国家、道、省、市、区县、街道、镇、社区和村庄按等级、比例尺与碰撞优先级显示。
- **细化要素渲染**：覆盖商业区与零售区、学校、自然覆盖、城墙、城门、墙体、栅栏、喷泉、花园、运动设施、公共厕所、商店和公共服务设施等要素。
- **近景自主底图**：约 500 米及更近比例尺使用按需生成的三小时稳定快照；更近一级再叠加两分钟更新的实时明细。树木点绘制为独立树干与树冠，小面积林地生成稳定树群，大型林地保持二维林地纹理与真实边界；森林公园优先按公园显示。父级快照先完整显示，实时分片完整后原子接管，加载中或接口失败时仍保留稳定底图。

### 地形、林地与组合视图

- 合格山地、荒原、灌丛及山区邻近小山显示坡面明暗、纹理和等高线；明确命名的小山保留，普通城市小林地、森林公园和明确平原遵守各自排除规则。
- 同一山岭内部符合真实几何关系的林地与荒原共用连续坡面。梅岭、桃林和曦曙山上的园林保留自身颜色、纹理与标注，并沿用所在山体的高度场；水体、河流、道路和建筑保持可见。
- 完整地形快照、空间分包及预制概览材质先显示，后台完成解压、解析与近景细化；复用 GPU 网格和浏览器持久缓存，拖拽及缩放期间保留已经加载的地形。新一代资产校验完整后才替换，失败继续使用旧快照。
- 标准和深夜地图的透视地形使用已有网格高程，不另加独立山体。后台转换配对高程及材质瓦片，完整近景接管概览，水体内部参与河谷约束并保留岛屿。首次透视准备仍可能较慢，缓存不能消除所有加载等待；当前属于制图推断，不是实测 DEM 或物理侵蚀、水动力模拟。
- 交通与地形独立勾选，可同时开启或关闭；交通图层仍可筛选线路类别。关闭地形后，基础林地树冠纹理继续显示。

### 交通与导航

- 显示并检索地铁、轻轨、有轨电车、公交和铁路线路。
- 支持换乘站合并、线路颜色、站点详情与交通视图。
- 全图同名铁路站按原始位置在固定代表点 350 米内合并显示，完整汇总正式线路、方向和服务；显示去重不改变导航图。不同名称、远处同名站、独立地铁和公交站继续分离，北沪确认规则优先。
- 铁路、地铁、有轨电车及公交按原始站名和系统分别显示；津川铁路“津川”与地铁“津川火车站”分开设站。同系统同名站台继续按既有距离去重，多线地铁换乘继续汇总；显示来源在三小时快照、后台收集及实时融合中保留，不修改导航图。
- 交通总览按数据代际缓存车站和空间索引，覆盖范围内复用绘制对象；铁路与公交实时收集在后台完成，透视交通无需等待全部底图资源。
- 提供步行、骑行、驾车和公共交通导航，并处理地铁与公交之间的换乘。
- 支持线路票价、分段计费、里程计费和上级 `collection` 票价规则继承。
- 全国交通、铁路连接、车站入口和服务信息以版本化 JSON 快照随项目保存；GitHub Actions 每三小时重建，只有数据语义变化且校验通过时才提交和部署。
- 交通视图的当前城市轨道网络与近景公交站使用固定地理分片，和建筑快照一样采用三小时边缘缓存；过期时先返回旧数据并在后台刷新。

### 三维建筑与动态覆盖层

- 华域标准与华域深夜从 OGF Overpass 按固定地理分片读取建筑轮廓，不依赖官方 Vector 建筑的较长更新周期。
- 建筑从约 5 km 比例尺开始按需加载，支持 `height`、`min_height`、楼层推导、复合多边形和 `building:part`。
- Cloudflare Pages Worker 为建筑接口提供三小时边缘缓存；约 500 米使用 `z14` 建筑分片，约 300 米使用更细的 `z15` 分片，避免密集城区单片过大。冷启动先保留发布建筑兜底，全部可见实时分片完整后原子接管；移动到新范围时继续保留上一份完整实时快照，避免半成品与发布建筑叠加。
- 空中花园和高架绿地按高度绘制，并与建筑模型保持正确遮挡关系。
- 明确标注的花园和花坛近景增加固定布置的花簇、矮灌木及观赏树；尊重边界、孔洞和屋顶高度，避让道路、水体、建筑及亭子，沿用后台模型与三小时缓存。山上园林继续共用所在山体的连续坡面。
- 普通建筑、古建筑和亭子模型读取有效 `building:colour/building:color` 与 `colour/color` 标签；独立屋顶优先读取 `roof:colour/roof:color`。支持颜色名、十六进制和 RGB/HSL，无效值回退到既有日夜配色。
- 亭子与凉亭仅按明确类型标签识别点、面和多面关系，名称带“亭”不会改变普通建筑分类。面状亭子保留原始轮廓、薄地台、内收边柱及自适应中心柱，点状亭子按可用空间避让道路，公交候车亭单独处理。
- 透视中地面道路、河流与贴地山体先绘制，树木、建筑、墙、亭子和站棚共用模型深度遮挡；保留实际高度与中空结构，异步更新后继续应用相同顺序。
- 官方 Vector 视图保持独立，不会被华域自建建筑模型替换。

### 地图下载

- 支持行政区边界、所选下级区划与坐标范围，导出 PNG、JPG、TIF、SHP 或 OSM。
- 可选择是否包含已确认的行政中心点；关闭后图片排除点符号、地名注记及点图例，也不补画区域中央的替代文字。矢量文件不附行政中心点图层或节点，行政边界及其名称属性保留。图片标题、坐标信息与来源说明保留；OGF 底图自带标注不受此开关影响。
- 图片长边可选 1200、2400（默认）或 4800 像素，并提前显示实际尺寸。PNG、JPG、TIF 和矢量 ZIP 附带的底图均使用所选尺寸，TIF 同步保留正确的像元大小和空间参考；纯矢量下载不受图片分辨率影响。

## 数据与更新方式

华域地图的不同内容采用不同的数据管线。“实时”表示按需读取当前 OGF 数据，并不等同于毫秒级推送；实际显示时间仍受 OGF 同步、Overpass 响应和缓存影响。

| 内容 | 数据来源 | 更新方式 |
| --- | --- | --- |
| 建筑与部分动态覆盖层 | OGF Overpass | `z11-z15` 分片读取；近景使用更小的 `z15` 分片，边缘与已打开视图稳定缓存三小时 |
| 约 500 米及更近的常规底图 | OGF Overpass | `z13-z14` 三小时快照；`z15` 边缘两分钟更新，但已完整加载的当前视图稳定保留三小时 |
| 道路、水体、土地利用和普通地名 | OGF OpenMapTiles | 跟随 OGF 矢量瓦片的生成周期 |
| 公共交通、铁路与导航辅助数据 | 三小时交通分片 + 仓库 JSON 快照 | 当前视野按请求后台刷新；全国包每三小时校验，有变化才自动发布 |
| 山体地形 | 已计算的概览材质 + 空间 JSON 快照 + 近景按需分片 | 首次直接显示概览，后台细化并缓存完成的网格；三小时工作流同步重建，页面每五分钟检查新版 |
| 华域标准与深夜样式 | 项目样式文件 | 修改、验证后随网站部署 |
| 精细规则与局部修正 | 应用代码和配置 | 经过回归测试后版本化发布 |

因此，建筑、近景自主底图和交通视图当前范围能够较快反映 OGF 修改。约 500 米及更近时，完整实时视口会替换常规地表、水体、道路和铁路的旧矢量层；体育、花园、桥隧、航空、行政边界和既有注记继续使用专门图层。缩得较远时仍使用 OGF 官方瓦片；全国交通包由定时工作流重建。这仍是三小时级刷新和缓存架构，不是毫秒级推送。

## 项目结构

```text
.
├─ site/                    Cloudflare Pages 的完整生产站点
├─ releases/                可回退的完整历史发布包
├─ release/                 当前站点文件的 SHA-256 清单
├─ scripts/                 清单、校验和发布归档脚本
├─ docs/                    中文运维与密钥配置文档
├─ .github/workflows/       自动部署和线上健康检查
├─ release.json             当前生产基线与校验参数
└─ package.json             本地维护命令
```

`site/` 是实际部署内容，包含应用代码、日夜样式、交通与导航数据、浏览器端依赖以及 Cloudflare Worker。`releases/` 保存可独立恢复的完整版本，避免后续实验覆盖稳定基线。

## 本地运行与校验

维护环境需要 Git 和 Node.js 20 或更高版本。克隆仓库后可先执行：

```powershell
npm run dev -- 45126
npm run verify
npm run check:data
npm run data:update:check
npm run probe:live
npm run verify:online
```

- `npm run dev -- 45126` 在本机启动同时支持静态站点和 Pages Worker 接口的开发服务器。
- `npm run verify` 检查站点文件、版本信息、构建约束和 SHA-256 清单。
- `npm run check:data` 检查交通、铁路、站口、机场与地形快照是否超过 14 天未更新。
- `npm run data:update:check` 离线检查七份静态数据的结构、数量、ID 与几何完整性。
- `npm run data:update:dry` 从 OGF 完整生成候选数据，但不替换 `site/`。
- `npm run data:update:resume` 复用最近一次失败运行中已成功的分块，从断点继续。
- `npm run data:update` 手动统一更新交通、铁路、铁路连接、车站接入、机场和地形快照；替换前自动备份并校验，本地运行不会部署网站。
- `.github/workflows/data-refresh.yml` 每三小时自动执行同一更新器；地形完整重建后更新生成时间，即使几何不变也发布新鲜快照。查询不完整或校验失败时不替换生产数据，成功时使用既有生产凭据部署 Cloudflare。
- `npm run probe:live` 直接探测 OGF 实时底图数据源及返回内容。
- `npm run verify:online` 检查生产站点与建筑接口是否可访问。
- `npm run manifest:update` 在明确修改 `site/` 后重建发布清单。
- `pwsh ./scripts/create-release.ps1` 创建新的完整发布归档。
- `npm run archive:project` 在项目外创建包含源码、站点、文档、工作流和历史发布包的整项目存档，并生成独立 SHA-256 清单。

本地开发服务器启动后访问 `http://127.0.0.1:45126/`。只查看静态页面时也可以打开 `site/index.html`；涉及实时建筑、实时底图接口和生产环境行为时，应使用本地开发服务器或 Cloudflare Pages 测试。

统一数据更新器只使用 Node.js 20+ 内置功能，仓库克隆到 Windows、macOS 或 Linux 后均可运行，不依赖 Codex、大模型、Edge、Playwright 或本机绝对路径。Windows 也可双击或在终端运行 `update-data.cmd`，macOS/Linux 可运行 `sh update-data.sh`。失败候选、日志和成功替换前的备份保存在 `.data-update/`，该目录不会提交 Git；人工维护的 `site/transit-services.json` 始终保留。

## 版本说明

### 7.0：同源透视地形与相机高亮

已有山体材质、高程和等高线共用同一网格；透视使用原材质位置与图层 ID，将高程及材质在后台转为配对瓦片，让山上的道路、水体、园林和模型贴地。保留有效高程约束、完整水体内部河谷、岛屿孔洞、连续山岭与森林公园排除规则；完整细化范围才接管概览，失败继续使用上一份完整地表。空间索引、预热和有界缓存减少重复转换，恢复俯视复用原 GPU 网格；首次准备仍可能需要等待，不宣称已经消除所有卡顿。

全图行政区、下级区划、地点、道路与下载范围高亮跟随实际透视相机，保留原始轮廓、多面区域和孔洞，不随相机手势反复上传整份边界。修复俯视缩放与窗口变化后的画布重投影，以及透视小数缩放退出时两个控制器比例不同的问题。已有模拟卫星、下载点要素与注记同步、铁路和地铁分别设站、模型缓存、三小时 GitHub Actions 更新及页面五分钟新版检查继续保留。

### 6.8：下载注记与点要素同步

取消“下载点要素”时，PNG、JPG、TIF 及底图合成图一并排除点符号、点图例和地名注记，包含没有确认行政中心时的区域中央替代文字。边界及矢量名称属性继续保留，图片标题、坐标信息和来源说明继续显示。已有模拟卫星、花园建模、交通系统分别设站、地形与模型缓存，以及三小时快照更新沿用上一版。

### 6.5：地图渲染与更新整合

相较上一次 README 对应的 `5.5-huayu-mountain-landscape-continuity-v1`，本次新增明确亭子标签识别与建筑颜色支持，更新前端识别、结构物查询和旧缓存失效，并加入点、面、关系、模型部件及日夜配色的回归检查。已有的连续山岭、山上园林、贴地等高线、快照预加载、后台缓存及模型遮挡整理为 6.5 的功能基线，历史 5.4 与 5.5 发布包继续保留。

亭子类型支持 `building/building:part/man_made=pavilion/gazebo`、`leisure=gazebo`，以及带 `shelter_type=pavilion/gazebo/picnic_shelter` 的 `amenity=shelter`。只有名称含“亭”、普通遮蔽物或普通建筑不因此变成亭子。建筑专用颜色优先于通用颜色，独立屋顶颜色不改写墙面；模型几何、高度、中空结构和地台材质保持原有规则。

### 6.6：山地高度场与加载优化

建筑、亭子和墙体的解析与几何生成移入后台 Worker，已处理模型在浏览器中保存三小时，重新打开可复用；模型算法变化时自动失效，缓存不可用或启动缓慢时继续网络加载。中远景减少细碎分片请求，近景保持完整模型，完整建筑快照继续原子接管。模型提交和体育场细节只等待所需样式和自身数据，不再等待地图的所有其他资源。

已访问区域的模型缓存扩大并改为按最近使用和容量淘汰：建筑、结构物内存各最多 256 分块，几何估算预算分别为 48 MiB 与 16 MiB；浏览器持久缓存合计最多 1024 分块、256 MiB，升级迁移旧缓存，三小时数据有效期继续保留。显示源只保留当前区域及有限的已访问邻近分块，往返于已覆盖区域时不重新索引或上传模型；远区域返回复用解析结果，按需提交显示数据。额外邻近模型限制为最多 128 分块，建筑 12 MiB、结构物 4 MiB，当前完整可见模型优先，不把全部浏览记录常驻绘制。容量数值是几何估算预算，不代表浏览器整体内存上限。

缓存启动较慢时网络并行加载，有效缓存若随后先到仍可直接复用，并取消多余网络请求；缓存无法返回时网络照常完成。后台保留轻量读写诊断，便于区分缓存未命中、存储不可用与读取稍慢，页面功能中不增加技术选项。

拖拽和缩放期间保留已显示的模型与地形，停止交互后再合并新数据、细化和切换所有权；稳定图层不重复调整顺序。地形只向 GPU 提交可能进入视野的连续三角形批次，保留完整缓存网格、原始高程与遮罩；山上园林衔接在后台处理，预制概览读取与近景计算分开执行。对应区域的原始分包完整并应用后，细化网格才接管概览，避免加载中的空白网格挡住山体。相关缓存、失败回退、手势、模型遮挡和地形几何检查已纳入整包验证。冷加载时间仍受数据源和网络响应影响。

### 当前地形限制

6.6 接入山地高程约束高度场：使用所有有效 `ele` 峰点、垭口及其他高程点，取消前八个峰点和 2500 米限高；观测点直接细分现有材质网格，坡面明暗和等高线共用同一场，河谷和边缘平滑不再改变这些点的标注海拔。新增、修改和删除的高程随三小时完整更新自动纳入，森林公园、普通小林地和明确平原继续排除。

本阶段暂忽略平地起伏；稀疏高程之间仍是连续插值与推断山脊，不等于完整实测 DEM，也没有实现物理侵蚀模拟。既有地形保持贴地材质，不增加独立透视山体层。`node scripts/rebuild-terrain-height-field.mjs` 可在保留现有山体几何和上下文的前提下，重新读取高程并生成完整候选快照；校验成功才原子替换，失败保留上一版。

### 5.5 阶段保留的功能基础

交通视图允许继续选择普通地点；地图视图菜单新增持久化的“点击选择要素”开关，关闭后仍可拖动、缩放、旋转，并保留测量与导航准星选点。透视状态下选择地点不再退出当前视角，华域标准、华域深夜与 Vector 三种矢量图层之间切换时会继承中心、缩放、倾斜角和旋转角。

本次交通站点补丁同时读取点状车站以及按面状 way/relation 绘制的车站，并将贴近客运轨道的面状车站中心吸附到现有线路。所有 `route=train` 线路均归入“铁路”图层；津川城铁、北沪望铁、高阳金铁与申铁等已登记市域铁路不会再随“地铁”图层显示，但仍可参与公交地铁公共交通导航。普通国铁仍只参与铁路显示与铁路导航。

林地树冠纹理属于基础地图，在地形关闭时依然显示，近景实时底图接管后也保留；地形开启后，合格山地区域才在原有二维材质里绘制较浅的绿色、山脊明暗和等高线。多尺度不规则明暗增加层次感，纹理与等高线仍为一次绘制，几何始终贴地。山体查询不再预先用名称结尾筛掉林地，客户端同时识别主名称、中文名、别名、山脉等命名，以及大林地内已标注的山峰；面积至少 25 平方公里的区域性林地也参与地形材质，不会仅因无名被跳过。普通小林地和森林公园继续排除；明确命名的小山体及符合邻近山区规则的碎片仍保留。明暗与等高线属于推断制图材质，不是真实测量地形。平章至雁华仍固定为“平章至津川、津川站内换乘、乘津川城铁雁华线至雁华”，其他交通与导航规则不变。

铁路导航继续把主线客站现有的 650 米车站复合体范围用于站内轨道关联；津川站因此同时覆盖津川城铁、津池铁路、岭东线和镇治高铁。物理轨道已经连通的方向保持贯通直达，只有独立轨道组件之间增加站内换乘和既有铁路换乘等待时间。普通铁路站原有的线路吸附与换乘范围保持不变。

上一构建 `5.5-huayu-mountain-coverage-valleys-v1` 保留既有主山脊、支脉、树冠纹理与等高线效果，修正网格预算不足导致的半片山体，按完整真实边界保留细长延伸，不再按比例或十二个面上限丢弃多面山林的子区域。远景自适应使用 z6–z9 分片覆盖整个视野，GL z5.5 开始加载。水体、河流、道路和建筑绘制在山体材质上方；水面与建筑真实轮廓同时从材质遮罩中排除，以兼容渲染器提前绘制不透明面的行为，避免仅调整顺序后仍被覆盖。实际河道和湖岸约束同一高度函数，使岸边下降、周围坡面上升，明暗与等高线一起呈现谷地。没有新增地形图层或抬升几何。旧缓存先显示，并在后台补齐水体和边界数据；三小时更新、普通小林地及森林公园排除规则保留。效果仍为二维推断制图，不是真实测量地形。

山体优先读取 `terrain-preload-manifest.json` 中的已计算概览材质，以及当前视野对应的空间快照；概览和细节属于同一个原有材质，按地理块接管，避免叠加变暗。分片在后台解压与解析，近景细节网格和遮罩也在后台计算；IndexedDB 保存最多 96 块完成的材质结果，几何、高度、河道、遮罩或材质算法改变时缓存失效。完整 `terrain-preload.json.gz` 与其 `contextSnapshot` 要素包共同构成兼容与离线兜底，逐包校验后才替换旧数据，单文件保持在 Pages 大小限制内。新发布包按完整覆盖范围替换旧山体，已删除山体不会被旧分片重新带回。三小时内远景直接复用发布包，近景、覆盖范围外或过期时按需补充；失败先保留旧快照。谷地首先使用快照中的完整河流和水体几何，再结合底图中已经加载的要素。拖拽期间延后细化，保留已经上传到 GPU 的材质。

地图图层菜单不再把普通视图与交通视图设为互斥选项：基础地图始终存在，交通和地形可分别开启、同时开启或同时关闭，默认保持地形开启、交通关闭。关闭地形会隐藏山地明暗、等高线、山名与山峰标注，保留基础林地的树冠纹理，并中止尚未完成的地形瓦片请求；三小时缓存继续保留，再次开启直接复用。树木、体育场、道路与建筑仍属于基础地图，不随地形开关关闭。

树木与体育场的加载逻辑不变：`natural=tree` 点要素仅在 `z15` 明细瓦片渲染为独立树干和树冠，`z14` 保留小面积林地的确定性树群；体育要素仍随中心优先瓦片逐块显示。小面积林地只作为二维林地或树群，森林公园以公园面为主并可保留树木，两者都不会被提升为山体。合格山地区域的坡面明暗、分层色彩和等高线使用同一套连续高度函数；没有实测峰顶时使用稳定且克制的推断山脊，不把结果冒充真实 DEM。旧的周期等高线、随机同心圈和阶梯挤出保持停用，三小时地形快照、实时底图 v8 与建筑模型 v15 保持不变。

亭子继续使用当前 OGF 原始面作为屋顶与 0.14 米薄地台，边柱向面内收拢并增加自适应中心柱，四周保持通透。墙、栅栏和亭子继续使用独立轻量结构物分片；建筑、结构物、当前城市交通与近景公交均保留三小时缓存和完整快照接管机制。交通全国预加载包在视图打开期间每五分钟重验证，全国交通、铁路连接、站口和机场包由 GitHub Actions 每三小时重建，只有数据变化且校验通过时才提交与部署。

近景 `z15` 实时底图细节继续叠加完整的 `z14` 三小时快照；体育场、行政区层级、线路站序、环线长度、模糊行政区搜索、选择开关和相机状态保持既有规则。既有 5.4 与 5.5 构建保存在 `releases/`，新构建不会覆盖历史存档。
