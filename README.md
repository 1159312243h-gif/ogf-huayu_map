# 华域地图

**当前项目版本：5.5**

当前构建：`5.5-huayu-mountain-neighbors-v1`（5.5.62）。已确认的大山实际边界周围 2 公里内，面积至少 1 万平方米的林地小山也进入既有山体材质；独立城市小林地、森林公园与明确标注的平原仍按原规则显示，新接纳的小山不会继续向外连锁扩张。前端、实时查询和发布快照采用同一分类，远景预算为邻近小山保留位置。发布快照重分类保留数据原始生成时间，通过分类版本替换浏览器旧缓存。沿用山体高于用地、水体道路建筑高于山体的绘制规则，三小时完整快照生成、五分钟新版检查和失败保留旧快照；同时修复 Cloudflare 压缩快照传输兼容性。

[在线访问华域地图](https://ogf-atlas.pages.dev/)

华域地图是基于 [OpenGeofiction](https://opengeofiction.net/)（OGF）数据构建的中文地图应用。项目不仅包含可直接部署的网站，还包括华域标准与深夜样式、交通数据快照、导航逻辑、实时三维建筑服务、版本归档、校验脚本、自动部署流程和中文运维文档。

项目目标是在保留 OGF 数据开放性和持续更新能力的基础上，提供更完整的中文地图表达：从国家和行政区到城市街道、公共交通、建筑、城墙、花园和各类公共设施，都按照统一的视觉与交互规则呈现。

## 主要功能

### 华域地图样式

- **华域标准**：默认基础图层，针对道路、行政边界、地名、水体、土地利用和各类设施重新设计。
- **华域深夜**：为夜间浏览提供独立的深色配色，保留道路、交通和土地利用层级。
- **官方底图对照**：OGF-Carto、Topo、CyclOGF、6ma 和官方 Vector 仍可按需切换。
- **多级标签与边界**：国家、道、省、市、区县、街道、镇、社区和村庄按等级、比例尺与碰撞优先级显示。
- **细化要素渲染**：覆盖商业区与零售区、学校、自然覆盖、城墙、城门、墙体、栅栏、喷泉、花园、运动设施、公共厕所、商店和公共服务设施等要素。
- **近景自主底图**：约 500 米及更近比例尺使用按需生成的三小时稳定快照；更近一级再叠加两分钟更新的实时明细。树木点绘制为独立树干与树冠，小面积林地生成稳定树群，大型林地保持二维林地纹理与真实边界；森林公园优先按公园显示。父级快照先完整显示，实时分片完整后原子接管，加载中或接口失败时仍保留稳定底图。

### 交通与导航

- 显示并检索地铁、轻轨、有轨电车、公交和铁路线路。
- 支持换乘站合并、线路颜色、站点详情与交通视图。
- 提供步行、骑行、驾车和公共交通导航，并处理地铁与公交之间的换乘。
- 支持线路票价、分段计费、里程计费和上级 `collection` 票价规则继承。
- 全国交通、铁路连接、车站入口和服务信息以版本化 JSON 快照随项目保存；GitHub Actions 每三小时重建，只有数据语义变化且校验通过时才提交和部署。
- 交通视图的当前城市轨道网络与近景公交站使用固定地理分片，和建筑快照一样采用三小时边缘缓存；过期时先返回旧数据并在后台刷新。

### 三维建筑与动态覆盖层

- 华域标准与华域深夜从 OGF Overpass 按固定地理分片读取建筑轮廓，不依赖官方 Vector 建筑的较长更新周期。
- 建筑从约 5 km 比例尺开始按需加载，支持 `height`、`min_height`、楼层推导、复合多边形和 `building:part`。
- Cloudflare Pages Worker 为建筑接口提供三小时边缘缓存；约 500 米使用 `z14` 建筑分片，约 300 米使用更细的 `z15` 分片，避免密集城区单片过大。冷启动先保留发布建筑兜底，全部可见实时分片完整后原子接管；移动到新范围时继续保留上一份完整实时快照，避免半成品与发布建筑叠加。
- 空中花园和高架绿地按高度绘制，并与建筑模型保持正确遮挡关系。
- 官方 Vector 视图保持独立，不会被华域自建建筑模型替换。

## 数据与更新方式

华域地图的不同内容采用不同的数据管线。“实时”表示按需读取当前 OGF 数据，并不等同于毫秒级推送；实际显示时间仍受 OGF 同步、Overpass 响应和缓存影响。

| 内容 | 数据来源 | 更新方式 |
| --- | --- | --- |
| 建筑与部分动态覆盖层 | OGF Overpass | `z11-z15` 分片读取；近景使用更小的 `z15` 分片，边缘与已打开视图稳定缓存三小时 |
| 约 500 米及更近的常规底图 | OGF Overpass | `z13-z14` 三小时快照；`z15` 边缘两分钟更新，但已完整加载的当前视图稳定保留三小时 |
| 道路、水体、土地利用和普通地名 | OGF OpenMapTiles | 跟随 OGF 矢量瓦片的生成周期 |
| 公共交通、铁路与导航辅助数据 | 三小时交通分片 + 仓库 JSON 快照 | 当前视野按请求后台刷新；全国包每三小时校验，有变化才自动发布 |
| 山体地形 | 仓库地形 JSON 快照 + 近景按需分片 | 首次直接显示发布包；三小时工作流完整重建，页面每五分钟检查新包并保存到浏览器 |
| 华域标准与深夜样式 | 项目样式文件 | 修改、验证后随网站部署 |
| 精细规则与局部修正 | 应用代码和配置 | 经过回归测试后版本化发布 |

因此，建筑、近景自主底图和交通视图当前范围能够较快反映 OGF 修改。约 500 米及更近时，完整实时视口会替换常规地表、水体、道路和铁路的旧矢量层；体育、花园、桥隧、航空、行政边界和既有注记继续使用专门图层。缩得较远时仍使用 OGF 官方瓦片；全国交通包由定时工作流重建。这仍是三小时级刷新和缓存架构，不是毫秒级推送。

## 项目结构

```text
.
├─ site/                    Cloudflare Pages 的完整生产站点
├─ releases/                可回退的完整历史发布包
├─ release/                 当前站点文件的 SHA-256 清单
├─ scripts/                 清单、校验和发布归档脚本
├─ docs/                    中文运维与密钥配置文档
├─ .github/workflows/       自动部署和线上健康检查
├─ release.json             当前生产基线与校验参数
└─ package.json             本地维护命令
```

`site/` 是实际部署内容，包含应用代码、日夜样式、交通与导航数据、浏览器端依赖以及 Cloudflare Worker。`releases/` 保存可独立恢复的完整版本，避免后续实验覆盖稳定基线。

## 本地运行与校验

维护环境需要 Git 和 Node.js 20 或更高版本。克隆仓库后可先执行：

```powershell
npm run dev -- 45126
npm run verify
npm run check:data
npm run data:update:check
npm run probe:live
npm run verify:online
```

- `npm run dev -- 45126` 在本机启动同时支持静态站点和 Pages Worker 接口的开发服务器。
- `npm run verify` 检查站点文件、版本信息、构建约束和 SHA-256 清单。
- `npm run check:data` 检查交通、铁路、站口、机场与地形快照是否超过 14 天未更新。
- `npm run data:update:check` 离线检查七份静态数据的结构、数量、ID 与几何完整性。
- `npm run data:update:dry` 从 OGF 完整生成候选数据，但不替换 `site/`。
- `npm run data:update:resume` 复用最近一次失败运行中已成功的分块，从断点继续。
- `npm run data:update` 手动统一更新交通、铁路、铁路连接、车站接入、机场和地形快照；替换前自动备份并校验，本地运行不会部署网站。
- `.github/workflows/data-refresh.yml` 每三小时自动执行同一更新器；地形完整重建后更新生成时间，即使几何不变也发布新鲜快照。查询不完整或校验失败时不替换生产数据，成功时使用既有生产凭据部署 Cloudflare。
- `npm run probe:live` 直接探测 OGF 实时底图数据源及返回内容。
- `npm run verify:online` 检查生产站点与建筑接口是否可访问。
- `npm run manifest:update` 在明确修改 `site/` 后重建发布清单。
- `pwsh ./scripts/create-release.ps1` 创建新的完整发布归档。
- `npm run archive:project` 在项目外创建包含源码、站点、文档、工作流和历史发布包的整项目存档，并生成独立 SHA-256 清单。

本地开发服务器启动后访问 `http://127.0.0.1:45126/`。只查看静态页面时也可以打开 `site/index.html`；涉及实时建筑、实时底图接口和生产环境行为时，应使用本地开发服务器或 Cloudflare Pages 测试。

统一数据更新器只使用 Node.js 20+ 内置功能，仓库克隆到 Windows、macOS 或 Linux 后均可运行，不依赖 Codex、大模型、Edge、Playwright 或本机绝对路径。Windows 也可双击或在终端运行 `update-data.cmd`，macOS/Linux 可运行 `sh update-data.sh`。失败候选、日志和成功替换前的备份保存在 `.data-update/`，该目录不会提交 Git；人工维护的 `site/transit-services.json` 始终保留。

## 版本说明

**5.5** 是当前开发版本。交通视图允许继续选择普通地点；地图视图菜单新增持久化的“点击选择要素”开关，关闭后仍可拖动、缩放、旋转，并保留测量与导航准星选点。透视状态下选择地点不再退出当前视角，华域标准、华域深夜与 Vector 三种矢量图层之间切换时会继承中心、缩放、倾斜角和旋转角。

本次交通站点补丁同时读取点状车站以及按面状 way/relation 绘制的车站，并将贴近客运轨道的面状车站中心吸附到现有线路。所有 `route=train` 线路均归入“铁路”图层；津川城铁、北沪望铁、高阳金铁与申铁等已登记市域铁路不会再随“地铁”图层显示，但仍可参与公交地铁公共交通导航。普通国铁仍只参与铁路显示与铁路导航。

当前 5.5 构建标识为 `5.5-huayu-woodland-terrain-modes-v1`。林地树冠纹理属于基础地图，在地形关闭时依然显示，近景实时底图接管后也保留；地形开启后，合格山地区域才在原有二维材质里绘制较浅的绿色、山脊明暗和等高线。多尺度不规则明暗增加层次感，纹理与等高线仍为一次绘制，几何始终贴地。山体查询不再预先用名称结尾筛掉林地，客户端同时识别主名称、中文名、别名、山脉等命名，以及大林地内已标注的山峰；面积至少 25 平方公里的区域性林地也参与地形材质，不会仅因无名被跳过。小于 1 平方公里的林地和森林公园继续排除；1 至 25 平方公里的普通林地须有山名或已标注山峰才进入地形材质。明暗与等高线属于推断制图材质，不是真实测量地形。平章至雁华仍固定为“平章至津川、津川站内换乘、乘津川城铁雁华线至雁华”，其他交通与导航规则不变。

铁路导航继续把主线客站现有的 650 米车站复合体范围用于站内轨道关联；津川站因此同时覆盖津川城铁、津池铁路、岭东线和镇治高铁。物理轨道已经连通的方向保持贯通直达，只有独立轨道组件之间增加站内换乘和既有铁路换乘等待时间。普通铁路站原有的线路吸附与换乘范围保持不变。

上一构建 `5.5-huayu-mountain-coverage-valleys-v1` 保留既有主山脊、支脉、树冠纹理与等高线效果，修正网格预算不足导致的半片山体，按完整真实边界保留细长延伸，不再按比例或十二个面上限丢弃多面山林的子区域。远景自适应使用 z6–z9 分片覆盖整个视野，GL z5.5 开始加载。水体、河流、道路和建筑绘制在山体材质上方；水面与建筑真实轮廓同时从材质遮罩中排除，以兼容渲染器提前绘制不透明面的行为，避免仅调整顺序后仍被覆盖。实际河道和湖岸约束同一高度函数，使岸边下降、周围坡面上升，明暗与等高线一起呈现谷地。没有新增地形图层或抬升几何。旧缓存先显示，并在后台补齐水体和边界数据；三小时更新、普通小林地及森林公园排除规则保留。效果仍为二维推断制图，不是真实测量地形。

山体首先读取随站点发布的 `terrain-preload.json.gz`，浏览器自动解压完整 JSON，新设备也可直接显示覆盖范围内的完整山形；浏览器通过 IndexedDB 持久保存发布包与最多 48 块近景分片，保留七天。新发布包按完整覆盖范围替换旧山体，已删除山体不会被旧分片重新带回。三小时内远景直接复用发布包，近景、覆盖范围外或过期时按需补充；失败先保留完整旧快照。查询复用关系内嵌的完整边界与空洞，避免再次下载成员线段。谷地复用底图已经加载的水体几何，不额外请求整个区域的河道。材质模型复用、计算分批让出主线程，更新完成前保留上一份完整绘制结果。

地图图层菜单不再把普通视图与交通视图设为互斥选项：基础地图始终存在，交通和地形可分别开启、同时开启或同时关闭，默认保持地形开启、交通关闭。关闭地形会隐藏山地明暗、等高线、山名与山峰标注，保留基础林地的树冠纹理，并中止尚未完成的地形瓦片请求；三小时缓存继续保留，再次开启直接复用。树木、体育场、道路与建筑仍属于基础地图，不随地形开关关闭。

树木与体育场的加载逻辑不变：`natural=tree` 点要素仅在 `z15` 明细瓦片渲染为独立树干和树冠，`z14` 保留小面积林地的确定性树群；体育要素仍随中心优先瓦片逐块显示。小面积林地只作为二维林地或树群，森林公园以公园面为主并可保留树木，两者都不会被提升为山体。合格山地区域的坡面明暗、分层色彩和等高线使用同一套连续高度函数；没有实测峰顶时使用稳定且克制的推断山脊，不把结果冒充真实 DEM。旧的周期等高线、随机同心圈和阶梯挤出保持停用，三小时地形快照、实时底图 v8 与建筑模型 v15 保持不变。

亭子继续使用当前 OGF 原始面作为屋顶与 0.14 米薄地台，边柱向面内收拢并增加自适应中心柱，四周保持通透。墙、栅栏和亭子继续使用独立轻量结构物分片；建筑、结构物、当前城市交通与近景公交均保留三小时缓存和完整快照接管机制。交通全国预加载包在视图打开期间每五分钟重验证，全国交通、铁路连接、站口和机场包由 GitHub Actions 每三小时重建，只有数据变化且校验通过时才提交与部署。

近景 `z15` 实时底图细节继续叠加完整的 `z14` 三小时快照；体育场、行政区层级、线路站序、环线长度、模糊行政区搜索、选择开关和相机状态保持既有规则。既有 5.4 与 5.5 构建保存在 `releases/`，新构建不会覆盖历史存档。

## 数据说明

地图内容来自 OGF 及本项目生成的数据快照。OGF 是虚构地理协作项目，地图中的地名、行政区、交通网络和建筑不代表现实世界。使用或修改数据时，请同时遵循相应数据源与项目依赖的许可要求。
