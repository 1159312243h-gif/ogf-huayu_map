# 华域建筑模型 v15

状态：本地候选版本，尚未部署
日期：2026-10-05

## 墙体透视互斥显示（v15 配套修正）

- 俯视模式继续显示普通墙和栅栏原有的外框与中心线；进入透视模式后，这些平面线层会关闭，只显示同一要素对应的立体挤出层。
- 这项修正消除了立体墙旁边重复出现、并可能穿过建筑的平面线，不改变城墙、墙体数据、结构物分片、三小时缓存或建筑模型几何。

## 建筑单一来源切换 v15

- 发布 Vector 建筑与当前 OGF 实时建筑不再同时可见；冷启动期间只显示发布建筑，所有可见实时建筑分片完整后才一次性切换。
- 移动或缩放进入新范围时继续保留上一份完整实时建筑快照，新的可见分片未完整前不会提交半成品，也不会重新叠加发布建筑。
- 面状、关系型亭子与面状公交候车亭跟随实时建筑所有权切换，避免它们与发布瓦片中的同一建筑轮廓重叠；节点亭子和节点站牌不受影响。
- 古建筑屋顶与轮廓现在和实时建筑主体使用同一显隐生命周期。道路、水体、体育、墙体、交通和三小时缓存规则均未改变。

## 亭子地台与柱位修正 v14

- 每个亭子在原始 OGF 面范围内增加 0.14 米薄地台，作为柱子和屋顶之间的落地层；地台不扩大、不简化原始亭面。
- 边柱从原始轮廓顶点向面内净空中心内缩，只有八边形柱体的全部顶点都位于亭面内时才生成，不再出现半根柱子伸出亭外。
- 面内增加一根中心柱；中心位置优先选择距离外边界与孔洞最远的候选点，窄面会自动缩小柱径，完整柱体放不下时才跳过。
- 屋顶仍按原始面架空，四周保持通透；高度参数、节点亭子道路净距、自适应大小、独立结构物分片和三小时缓存均不变。

## 开放式亭子模型 v13

- 面状与关系型亭子严格保留当前 OGF 原始轮廓作为屋顶范围，不再把该轮廓挤出成封闭实体。
- 节点型亭子读取同一 `z14/z15` 结构分片内的道路和步道中心线，根据道路估算半宽及 0.45 米留白动态确定屋顶半径；空旷位置可扩大到约 3.8 米，临路位置会缩至最低约 0.8 米。
- 显式 `diameter` / `width` 仍作为目标尺寸，但会受道路净距约束，避免亭顶明显压盖道路。
- 每个亭子拆成独立屋顶与 4–8 根边界立柱；立柱从地面延伸至檐底，中央不生成墙体或底座，透视视角可直接看见中空空间。
- 总高继续依次采用 `height` / `est_height`、`building:levels` 和 3.6 米默认值；屋顶厚度继续采用 `roof:height` / `building:roof:height` 或原有默认值，显式 `min_height` 保持有效。
- 结构物缓存升级为 `huayu-structures-v2-open-pavilions`，保证旧的实心亭子快照不会覆盖新模型；三小时刷新与失败保留策略不变。

## 亭子、墙与栅栏 v12

- 增加独立 `/api/structures/{z}/{x}/{y}.json` 轻量结构物分片，墙、栅栏和亭子不再依赖高密度建筑查询是否成功。
- 结构物分片读取全部 `amenity=shelter` 候选、`leisure=gazebo`、`man_made=gazebo|pavilion`、亭子建筑标签及名称明确的亭子，再在客户端排除公交候车亭、车站和服务岗亭。
- 面与关系沿用真实 OGF 轮廓；仅有坐标的节点默认生成约 1.7 米半径的八边形屋顶，显式 `diameter` / `width` 始终优先。
- 总高依次采用 `height` / `est_height`、`building:levels`，缺失时为 3.6 米；屋顶深度优先采用 `roof:height` / `building:roof:height`，缺失时约 0.8 米。
- 未标注底高的亭子只挤出架空屋顶，不生成封闭实心墙体；显式 `min_height` 或 `building:min_level` 始终优先。
- 公交候车亭、轨道车站与保安亭等服务亭不进入通用亭子模型。
- Worker 与浏览器直连回退使用相同选择器；v12 独立结构物缓存为 `huayu-structures-v1`，三小时刷新并在更新失败时继续保留旧快照。
- 建筑查询恢复为既有 `huayu-building-v5` 缓存模式，亭子不会再增加建筑请求的超时风险。

## 数据流

```text
地图可见范围
  -> 匹配视图层级的 z11-z15 建筑数据网格
  -> 建筑：/api/buildings/{z}/{x}/{y}.json
  -> 墙、栅栏、亭子：/api/structures/{z}/{x}/{y}.json
  -> Cloudflare Pages Worker 三小时边缘缓存
  -> 当前 OGF Overpass building way / relation
  -> 客户端按 OGF 对象 ID 合并
  -> 华域 GeoJSON fill-extrusion
```

- 外层地图 `z11+` 显示建筑；对应 MapLibre 内部 `z10+`，即当前界面约 `5 km` 比例尺。
- 建筑分片随视图逐级使用 `z11-z15`；约 500 米使用 `z14`，约 300 米使用 `z15`。全部级别稳定缓存三小时，较细分片用于限制密集城区单片数据量。
- 客户端最多同时读取 3 个分片，内存保留最近 72 个分片。
- 平移只补充新分片，远距离跳转会取消已离开视野的未完成请求；缩小仅暂停新请求，不清空已有分片缓存。
- 高度优先使用 `height` / `min_height`，其次使用建筑层数；无高度的宫殿、城门和具名传统建筑使用语义默认高度，其他建筑回退 3.2 米。
- 华域标准和华域深夜按中心优先渐进显示已经到达的实时建筑；未覆盖区域保留发布建筑，完整视口到齐后再关闭兜底。官方 Vector 完全不启用本模块。

## 能力边界

v4 提供全域按需覆盖：地图移动到 OGF 中任意区域时，都能用同一分片规则读取建筑。它没有预生成全国建筑。首次访问一个从未缓存的分片仍取决于 Overpass 响应速度；访问过的分片可直接命中边缘缓存。

若要求全国任意地点首次打开即稳定秒出，应每日从完整 OGF 数据生成 MVT/PMTiles，并保留当前接口作为短期实时补充或失败回退。

## 500 米快照与渐进显示

- 500 米底图使用 `z13` 三小时稳定快照；建筑使用更细的 `z14` 三小时分片。300 米建筑继续使用 `z15` 三小时分片。
- 建筑中心分片先完成先显示，不再被最后一个慢分片阻塞；加载期间发布建筑继续覆盖尚未返回的区域。
- 修复前 500 米冷缓存测试在 8 秒时已有 10/12 分片完成，但实时建筑仍为 0；渐进合并后这些已完成分片会立即显示。

## 空中花园屋面覆盖 v5

## 复合多边形与组合建筑 v7

- 对“无内环，且所有外成员都是自身带建筑标签的闭合 way”的组合关系，不再把关系整体挤出为默认高度，而是按各成员的 `height`、`min_height` 和层数独立建模。

## 稳定加载与近景分片 v10

- 新增 `z15` 建筑分片，近景不再解析覆盖数公里范围的高密度 `z14` 单片。
- 建筑请求与实时底图并行启动，不再等待底图完全接管。
- 发布建筑持续显示到全部可见实时分片完成；实时模型整批合并后一次替换，刷新期间保留上一完整模型。
- Worker 与浏览器建筑缓存改为三小时，停留同一区域不再每两分钟重新请求和重建 GeoJSON。
- 无明确高度的宫殿、城门和具名传统建筑使用语义默认高度，避免俯视轮廓存在而倾斜视角近乎贴地。
- 底图的当前完整视图同样稳定保留三小时；边缘 `z15` 数据仍可每两分钟为新请求后台更新。
- 调度器保留更早的视口刷新任务；全部可见建筑分片首次齐全时立即接管，后台批量更新则继续保留上一完整模型，避免跨城移动后停在备用建筑。
