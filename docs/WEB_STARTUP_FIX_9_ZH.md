# 网页空白与手机菜单修复（2026-11-23）

构建9.0-web-startup-v1。本记录区分本地故障回放、完整地图回放及正式部署，线上状态单独核验。

## 实际原因

线上390×844浏览器首次读取中，80秒时主程序仍在网络等待，主样式曾返回net::ERR_HTTP2_PING_FAILED。原页面没有独立的启动失败提示，形成只有外壳的空白地图。品牌模块样式另将手机导航强制设为12个等分列，与完整15入口及主样式横向网格冲突，造成部分按钮挤压、换排和重叠。原app在Leaflet地图和菜单初始化之前还等待矢量组件，组件慢或失败会继续阻塞已有可用功能。

## 修正

- 品牌样式移除对主导航的固定列覆盖，主导航使用48像素最小列宽，全部入口单行横向滚动，文字不折成竖条。
- 提前发现Leaflet与主程序资源；独立异步加载状态不依赖52个有序功能脚本全部执行。慢资源、必需脚本／样式失败显示重试，重试不清空账号、模型、草稿或存储。
- 原Leaflet基础地图、操作及真实HuayuAtlas接口先初始化，再后台准备所选矢量组件；保持原功能脚本执行顺序及建筑瓦片协议先于主程序执行。
- 矢量脚本和样式各最多等待12秒；组件失败保留可用地图和保存偏好，显式重试复用原处理器。底图资源15秒未就绪时采用原基础图临时回退，不永久改写保存偏好；恢复仍受网络可达性影响。
- 用户后续选择优先，迟到初始加载／重试不能覆盖新选择；晚到基础瓦片不能把仍需重试的矢量错误提示隐藏。地图已绘制后才到达的启动脚本能识别已有完成状态。

保留全部原入口、模型、颜色、日照、导航、账号、共享内容及两分钟／五分钟／三小时更新。不改原生运行环境和安装方式，网站发布后本地客户端按原完整程序校验和重启流程更新。未访问瓦片和查询仍需联网，不将状态提示框当作地图数据已取得。

## 验证

实际Chrome软件WebGL在360、390、430、680、1100像素宽度模拟矢量引擎失败；地图操作在等待引擎期间已可用，15入口不重叠、手机可滑至最后帮助并点击，程序无异常。重试成功加载实际捆绑引擎与图层；第三方源故意阻断，此项不冒充在线瓦片已成功。

另用相同既有完整公开响应回放主地图，390×844实际显示1818栋建筑、281个坡屋顶，保留三维模式，原偏好huayu不变，完整地图到达后加载提示隐藏，15入口宽48px且保持同一行，页面异常0。没有将回放时间冒充重新抓取OGF源数据。
