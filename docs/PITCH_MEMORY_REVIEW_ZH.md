# 大倾角模型加载优化验证

验收版本：`7.5-pitch-memory-v1`。验证于 2026-10-23 至 24 日进行，当时尚未提交 GitHub 或部署 Cloudflare；2026-10-26 纳入 `7.5-roof-only-v1` 发布，实际状态以 GitHub Actions 和线上检查为准。

复现位置：地址栏 `#map=16/14.63852/152.93546`，原生矢量比例 15。优化前，同一位置俯视约需 20 个建筑分块，大倾角需 598 块；结构物同样扩大。当前可见分块全部受到淘汰保护，原缓存容量不能有效约束这个请求集合。本地检查未直接复现用户截图中的浏览器内存不足崩溃，确认的是上述无界加载风险。

优化后，每类精细模型选择附近最多 32 块，三个并发；完整显示源及已访问邻块最多 64 块，建筑／结构物几何估算量分别限制在 12／4 MiB。密集区域缩减完整矩形窗口，窗口外和跨边缘建筑继续显示原生矢量。取消旧区域请求，并拒绝迟到或超预算结果进入模型内存。两分钟新鲜度、浏览器持久缓存、90° 相机、原始几何与三小时工作流保持原样。退出屋顶控制器时，不再访问已经销毁的底图样式，仍释放几何、材质和渲染器。

真实 Chrome 无头浏览器使用 1440×1000 视窗，先等完整建筑接管，再进行三轮 90°→50°→0° 切换，平移位置并旋转 0°／40°／80°。2026-10-24 00:03:21 至 00:05:53 的 13 次采样全部满足分块、并发、排队、缓存与显示源预算：大倾角当前范围 30 块，最终建筑及结构物缓存各 40 块；估算几何分别约 2.66／1.60 MiB。主线程 JS 堆采样峰值约 280 MiB、结束约 139 MiB，后半程有明显回落，无脚本错误或崩溃。这不是浏览器进程、Worker 或 GPU 的总内存测量，不能据此保证任意设备和多标签页永不内存不足。

首轮带截图的压力脚本在限时内未完成；随后将截图和画面检查单独执行，上述三轮压力测试完整完成。独立画面检查核对了 50° 下的道路、完整建筑与亭子、90° 实际相机、恢复俯视及模拟卫星保持 0°。切换时曾发现屋顶清理访问旧样式的问题，已补保护并加入资源释放回归；后续切换未再出现该异常。实网检查仍有上游 503 响应，未把网络请求全部成功当作验收结论。

已通过整包 `verify`、`test:data-update`、`data:update:check`、`check:data` 对应的 Node 脚本，以及模型加载、结构物、花园、设施、建筑材质与屋顶相关回归。新增检查覆盖完整窗口的数量及容量、原始轮廓跨边缘兜底、跨 180° 经线、手势期间固定查询视图、已取消结果迟到、单块过大回退及底图已销毁后的屋顶资源清理。数据抓取时间没有重新标记。
