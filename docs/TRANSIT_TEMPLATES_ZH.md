纸质横牌为横向路线配竖写站名，纵向灯箱为连续的纵向站序，杆挂牌突出线路号与开往方向；LCD 为分块到站信息，LED 为到站表列，墨水屏为黑白高对比布局。横版按可读宽度优先排满单行，实际容纳不下时才分行；纵版分栏保留全部站点，不截断末站。

运营资料优先读取具体方向关系，缺项沿明确的 route_master／network／operator／collection 等上级逐层查找，最近一层有值时使用该层；同层冲突不猜。再按完整运营方／网络名查询 OGF 中的运营安排，仅使用明确的公交服务标签，不拿公司办公时间当线路时刻。运营方补查失败保留完整站序及已读资料，并提示未读取成功。线路支持 opening_hours／service_times／operating_hours、start_time／first_departure、end_time／last_departure、charge／price／fare 与 currency、operator、interval／frequency；departures／departure_times／timetable 单列为发车时刻，不再混入班次间隔。时间表链接不作为时刻文本。长时刻表自动换行并扩展画布，全部条目保留；仅有逐班时刻时不强填间隔。可在运营资料中补填七项，限本页和图片，不写入 OGF 或共享版式；恢复原始资料可撤销补填。反向不生成未知方向时刻。电子到站数据未接入时仍明确“未接入”。

环线识别优先明确 roundtrip=yes/no；也支持同一起终点、首末同一站点的闭合序列和名称中的“循环／环线／Loop”等。临川大学“工医小循环”和“医文小循环”按循环线展示，用闭合曲线与本站／下一站表示方向，闭合处接回关系序列的后继；不打印环线／首站说明，不把序列开头当作运营起点。源序列重复首站的端点保留；选中重复端点后进入第二站，避免停在首站自循环。单站环线和反向预览同样处理，全部原始站序保留。

## 更多站牌样式

当前共 53 套内置模板，其中公交站牌有 26 种不同结构；新增样式仍为原创通用排版，不标作某城市官方复刻。

| 新增结构 | 排版及适用场景 |
| --- | --- |
| 米白紧凑横条 | 左侧线路号，右侧横向路线配竖写中文站名，多线路逐条叠放 |
| 青白左右分区灯箱 | 左侧方向及服务资料，右侧纵向站序；长线继续分栏 |
| 深色横屏多线路看板 | 左侧多线路总览，右侧各线完整站序，原宽 1920 像素；到站栏明确未接入 |
| 蓝白双列分卡 | 不同线路独立卡片，两列排列，更多线路向下展开 |
| 橙白公交枢纽索引 | 先列线路、方向、下一站和服务时间，再列各线完整站序；不编造站台号 |
| 紫白横写双语牌 | 中文横写、原始英文名另行展示，没有英文标签不生成翻译 |

其余新样式原宽 1440 像素，长线自动扩展高度。所有新样式支持单线路、同站多线路、PNG／SVG、统一下载清单及模板 JSON 导入／共享。公交横向站数按实际画布和可读字号自动计算，固定列数只用于轨道线路屏；纵向灯箱与左右分区布局自动分栏。原有六种公交布局、车载路牌与地铁模板保留。

公交不再显示公交之间的换乘线路清单，保留地铁／铁路／航空／轮渡等跨方式提示。只使用有类型的真实换乘信息；医院、学校的医／学标识须有明确 amenity 标签，不凭站名猜测。轨道导视仍沿用原换乘信息。

## 一个车站的多条线路

同一工作区把“显示范围”改为“同站多线路站牌”。示例直接提供大学城站的 28、56、104 三条虚构线路，图片内标注示例。

自动读取：在“按车站生成全部公交线路站牌”输入站名或 node/编号、way/编号、relation/编号，点击具体结果；也可在地图上选中公交站，点击“使用地图选中的车站”，交通站点弹窗有“制作本站全部公交线路站牌”。按该站直接公交关系读取各自方向／站序，支持节点及平台面，不按同名或距离把对向站并入。明确相邻 stop/platform 成对成员在同名及真实近距离校验后共用一次站序，但仍保留所选原始要素归属。未接入车站周边的所有无关系线路推断；未登记的线路应在 OGF 补好停靠关系。查询全部关系后自动切换整站显示。

手动操作：在原线路页搜索并读取具体公交方向／分段，选择本站，点击“将当前线路／方向加入本站牌”；再搜索下一条线路、选中相同站点编号并加入。已有本站编号能在新线路中精确找到时自动选中；对向站、同名但编号不同的站、轨道换乘线不能凭名称或距离并入。整合方向的主关系须先选具体分段。重复加入同一关系、端点及本站位置会更新原条目；可逐条移除或清空，失败保留旧清单。清单在本页内存保留，换线继续保留，刷新后不保留；可下载 PNG／SVG 保存整站图片。

- 横排纸质牌／杆挂牌：统一本站名，各线路完整站序分别叠放。
- 纵向灯箱：统一本站名，各线路纵列并排，更多线路换到下一组，各线长站序继续保留。
- 电子牌：上部多行到站表，每行分别显示线路、开往方向、下一站与两班到站栏；下部保留每条线路的完整站序。实时数据没有接入时仍显示“未接入”。

页面说明展示收录线路／方向数量和站点编号，图片不印这些统计。手动清单明确非全站完整；自动查询完成则标注“本站已登记公交关系查询完成”，只代表所选 OGF 要素直接登记的停靠关系，不保证未登记的现实线路。SVG 元数据及页面保留 OGF 数据时间；实际读取时间与源时间分开，部分返回、缺失站序、取消、切换站点不会覆盖旧站牌。线路数据仍与模板 JSON 分离，共享版式不附带当前站牌线路。

## 使用

1. 打开线路显示模板，可先查看明确标注的示例。
2. 在同页下方搜索并选中真实公交／轨道线路，待站序加载后自动填入模板。沿用当前方向／分段的已读取站序，不改变地图路线。
3. 选择公交站牌、车载路牌、地铁导视、LED 或 LCD。共 53 套，其中公交站牌 26 种结构、公交车厢屏 9 种，另有前后路牌与轨道导视／车厢屏；均是原创通用版式，并非各城官方同款复刻。
4. 可改配色、轨道线路屏每行站点数（公交横向按可读宽度自动排列），反向显示，或手动预览当前／下一站。显示为静态示意，未连接真实车辆位置、到站预报和车次表。
5. 下载 SVG 或 1×／2×／3× PNG；图片可加入统一下载清单。大图可放大滚动查看。所有已读站点在站牌／线路屏中保留，车载前后路牌主要展示终点和下一站。

## 导入与共享

“编辑与上传模板”下载 JSON，按同一格式编辑后导入；模板文件只含版式、作者、许可、来源，既不绑定某条线路，也不含当前地图资料。当前不支持直接把照片、RMG／RMP JSON、HTML、SVG 当作模板上传；不会从照片自动提取文字或布局。

准备共享需登录，会把模板带入原共享数据表单，经本机预览及服务端校验后由用户核对并确认发布。模板库按需查询“其他”类别下“线路显示模板”数据包，读取完整标准化记录并校验，不执行上传内容。编辑资料／删除沿用作者及管理员权限；修改正文时发布新版数据包，保留原件。准备过程保护既有草稿，不附带当前选中的地物几何。

格式为 huayu-transit-template-v1，包含 title、family、author、license、sourceUrl 与 style。family 支持 bus-stop、bus-rollsign、bus-interior、metro-guide、metro-led、metro-lcd；style 包含 background、text、muted、accent（六位颜色或 route）、columns（4–16）、shape（round 或 square），公交站牌另有 busLayout（strip、column、pole、lcd、led、ink、compact、split、wide、cards、hub、bilingual）。旧 JSON 缺少 busLayout 时沿用横排竖写布局；其他家族不能使用该字段。建议直接下载内置模板作为例子，未知字段会被拒绝。

## 助手与检查

助手的 get_transit_templates 返回实际模板编号和当前真实线路摘要；prepare_transit_template 使用该编号打开原界面预览。没有选中真实线路时必须先选线路；演示使用 demo 明确标注。display=line 预览单线路，display=station 预览公交同站多线路；后者 selected 须已有自动查询或用户收录的本站牌，demo 使用明确示例。助手新增 load_transit_station_template，使用当前选站或查询所得真实地点 ref，复用原界面读取全部已登记公交关系并预览；不共享或下载，不接受模型编造物体编号。

运行 node scripts/test-transit-station-data.mjs 和 node scripts/test-transit-templates.mjs，整包检查会包含模板回归。线路规则、助手接口、既有共享数据权限和站内帮助继续进行原有检查。此功能不修改数据抓取时间、地图建筑、导航或交通模拟。

## 统一排版规则

多条线路之间有明确的横线或竖线，灯箱与双列卡片同样适用，并压缩不必要的留白。闭合线路突出本站和下一站，使用曲线表示回接；不额外写环线、循环接首站等说明，不显示从1开始的站号暗示运营首站。关系的第一个成员是数据排列起点，不是运营首站的证据；全部原始站点及方向仍保留。规则覆盖所有城市、全部28套模板、原线路导视与PNG／SVG，不对某个校园或车站写专用分支。导视同样显示实际已读运营资料，公交不列其他公交的换乘清单；轨道换乘继续保留。

2026-11-19 修正：环线保留 from/to 明确的终点和下一站，没有终点标签则保留终点栏位并显示未提供，不把关系序列的开头／末尾猜作运营终点。总关系只有在已读全部直接方向端点一致时才共用端点；冲突或缺失不猜。环线的主线与回接线使用同一线宽，所有版式、单线路／整站及 PNG／SVG 一致，反向预览保留环线原终点。

所有线路的终点以所选线路关系的 to 为准，始发读取 from；普通线路同样不再用成员首末站补作起终点。缺失终点标为未提供；预览换向只调整站序，不互换属性，选择另一条真实方向关系后读取该关系的 from/to。
