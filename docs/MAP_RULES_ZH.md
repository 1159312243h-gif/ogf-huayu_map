# 用户确认的地图规则

整理日期：2026-10-12。本文保存用户在历次修改中确认的行为，作为后续渲染修改、性能优化、数据刷新和发布的验收条件。用户最新明确指示可调整相应规则；普通更新必须继承这些规则，不能恢复已经修正的问题。

规则适用于 `site/app.js`、`site/_worker.js`、`scripts/data-update/builders/`、快照构建、实时数据融合及定时更新。规则说明和现有回归检查共同维护；下表列出相关检查入口，不表示单个测试能替代所有视觉验收。

## 1. 树木、山体与公园的分类

- `natural=tree` 点要素渲染为树木；城市内小面积普通林地渲染为树群或基础林地，不能一律当作山体。
- 面状树群适度加密，按约每 1800 平方米一棵布置，单面最多 96 棵、单批最多 320 棵；先覆盖完整面内候选网格再按固定种子选取，不能按行提前截断导致另一侧空白。保留原始边界、孔洞及固定要素种子。单棵已标注树木的数量、尺寸与高度不受面状密度调整影响，不扩大山体或林地的分类范围。
- 下载旁提供独立地图设置，可选择经典柱形或自然树冠，默认保留经典模型。样式共用已有树木及花园观赏树的位置、实际高度、底部高度和避让结果；自然树冠采用共享深度的批量模型，不重新抓取数据、不重建地形、不清空建筑与结构物缓存。加载失败继续显示经典树木，底图切换清理旧 GPU 与监听。模拟卫星仍为平面树冠，不启用立体树木。
- 面状植被密度可选疏朗、适中或茂密，默认沿用当前加密后的完整数量；按要素固定种子选取嵌套子集，不在缩放、拖拽时重新随机，不删减已标注的单棵树或点状花园。花园花簇可独立关闭，保留花园地表、灌木与树木；设置在本机浏览器保存，可恢复渲染默认值，不更改原始数据、下载选项或三小时快照更新。
- 用户于 2026-10-13 确认先登记外部模型候选：阔叶树、松树、灌木、花簇、亭子、候车亭、喷泉、两款台北地铁入口、栅栏、围墙及平遥城墙参考。候选以独立设置保存，并纳入恢复默认；文件尚未取得时明确标为待导入，台北入口标为待授权文件，城墙扫描仅作参考、待轻量化。选择尚未取得文件的候选仍使用现有渲染，不触发地图重绘、下载、数据请求或缓存失效，不冒充已经安装的模型。排除用户否定的外部站牌、旧地铁入口及早期不写实植被；保留现有站牌、亭子标签识别、真实位置高度与面范围、森林公园排除、共享深度和模拟卫星平面规则。不购买或绕过平台限制；后续拿到合法文件后另行接入，不影响导航、原始数据或三小时更新。
- 明确命名的小山，即使面积小，也保留山体表达。大山周边符合现有真实距离、几何关系及山区条件的小山体也保留，不能因面积门槛漏掉。
- 用户于 2026-10-13 要求实现导入。候选支持本机 GLB 校验、交互预览、朝上轴、旋转及部件选择；确认合法取得及本机使用授权后，文件和来源记录原子保存到独立浏览器数据库，失败保留原模型。初步地图替换支持阔叶树、明确针叶标签的松树、花簇和灌木，沿用已有布点、密度、高度、避让和共享深度；未注明叶型的树使用通用阔叶候选，不依据名称猜测松树。模拟卫星始终保留原平面表达。单文件最多 24 MiB、24 个网格、10 万三角面、8 张最长边 2048 像素的贴图；本机模型总容量最多 128 MiB。现场替换仅接受单模型不超过 2 万三角面，单批不超过 256 实例和 40 万三角面；预算外保留原模型，固定顺序选择，拖拽缩放不重新随机。恢复默认不删除已导入文件，移除文件须明确确认。亭子、候车亭、喷泉、入口、墙与城墙可先导入预览保存，但专用几何适配未完成时须标为待适配，不能在地图上假装已替换或扩大真实面轮廓。拒绝损坏文件、外部贴图请求、不支持的压缩扩展与动态模型；使用同版官方 Three.js GLTFLoader，不执行模型附带脚本、不上传文件、不开设账户，不改变三小时更新和导航。公开发布候选文件需另行核验再分发授权。
- 用户下载的 Igor_K. 白桦 GLB 已核验文件内与来源页的 CC BY 4.0 许可、署名及完整性，可作为可选内置方案。保持经典模型为默认，不自动改选；首次选择白桦才获取同源、内容哈希命名的文件并校验 SHA-256，不携带平台登录凭据。使用完整单棵 `birch-1` 的树干和树叶（3414 三角面），不能每个树木点位种上原文件的整组四棵；不修改原始几何和贴图，叶片改为透明裁切以参与共享深度，并保留修改说明和署名。本机自行导入的同候选文件优先，恢复默认不删除它；移除本机文件后可恢复内置候选。内置文件不依赖 IndexedDB，仍受现场替换预算、真实位置高度、卫星平面和加载失败回退约束；其他候选以实际取得、校验及适配结果更新状态，尚未取得的继续待导入、待授权或参考。
- 森林公园优先作为公园，可显示树木；不能仅因名称含山、内部有峰点或面积大而变成山体。公园排除规则优先于一般山体候选规则。
- 内置白桦缩小后保留叶片透明裁切覆盖率，不能因普通贴图平均而只剩散点或整片消失。各级缩小贴图独立校正透明度，颜色按透明度加权并在线性空间缩小，真正的透明空隙保持透明；保留原始文件、近景贴图、几何与 0.3 裁切阈值。只在已核验白桦解析时准备一次共享贴图，缩放、拖拽不重算、不重复下载；不增加布点密度、尺寸或面数，不改其他导入材质、共享深度、卫星平面或三小时更新规则。
- 明确平原、平地林区保持平坦，不因林地面积大而生成山体。
- 用户于 2026-10-13 要求批量下载导入剩余候选。通过 Sketchfab 官方下载接口逐项核验 ID、下载状态和当前许可；本机输入的 API token 只在下载进程内使用，不写入文件、日志或浏览器存储，不提取网页登录资料、不购买或绕过限制。原件、来源及文件哈希保留，成功项不因其他项目失败而被删除。实际 GLB 校验及预览通过后才登记同源可选文件并保留署名；未取得、过大、模型组未选完整单体及专用适配未完成的状态必须如实区分。默认偏好、已导入文件、真实布点、共享深度、卫星平面、导航和三小时数据更新保持既有规则。
- 本批次已导入松树、单株灌木、雏菊、木亭、候车亭、喷泉、栅栏和围墙，连同白桦共九款；台北入口未开放下载，城墙扫描只保留参考原件。灌木只用完整单株 `Bush_medium_001_LOD0` 的枝干与叶片，保留祖先变换及引用贴图，叶片采用 0.3 透明裁切；候车亭仅移除辅助线，保留所有三角面与玻璃；喷泉转换旧式零镜面材质而保留贴图、几何、透明水体及变换，不得直接删除必需扩展冒充兼容。模型特定转换以已核验原件哈希为前提，可离线复现；预算、默认模型及专用结构物待适配状态继续保留。
- 用户随后要求完成城墙及剩余结构物的实际地图替换。现已接入亭子、候车亭、明确标签喷泉、栅栏、围墙与城墙：沿用既有来源、真实面轮廓、孔洞、方向、位置、标注高度和底部高度；不因名称猜测类别，不把城门替成墙段。模型与建筑、植被共用深度，墙段两端沿既有坡面调整，模拟卫星继续平面表达。面状亭子、候车亭只在完整实时建筑接管后替换，成功适配且预算允许才隐藏对应原模型；无法完整适配、加载失败或超预算时保留完整原要素。经典默认及用户选择保留，拖拽不重新下载模型，不改变导航和三小时快照更新。
- 栅栏只使用已核验组内的完整单段（300 面）；城墙原件保留，现场使用从固定原件哈希和固定范围裁出的墙段（4836 面、909868 字节），保留扫描砖墙、步道、垛口及纹理，剔除周边街道、车辆、草地和建筑，校正反射后的面朝向、封闭切端并公开修改说明。减面可离线复现，不在浏览器或三小时工作流中执行。连同植被现有十款可替换文件。
- 用户随后取消地铁出入口模型替代方案：设置与批量候选目录移除该分类及两款台北入口，不再保留待导入选项。下拉选项仅显示模型名称，去掉括号中的导入状态及“轻量”等附注，实际文件、准备和应用状态继续显示在下方说明。旧偏好中的入口选择忽略，其他模型选择与已导入文件保留；此调整不移除实际地铁站、既有入口渲染或交通导航。
- 用户要求以默认形态模型发布到 GitHub 和 Cloudflare：新浏览器默认使用经典树木及原有结构物，十类模型替代方案均为“沿用现有模型”，不得把维护者预览时的选择写成站点默认。替代模型继续可选，既有用户偏好与本机导入文件保留；默认打开不请求替代 GLB。
- 合格荒原、灌丛和山地草地仍参与山区表达，较平坦的荒原采用柔和起伏；不能把城市中的普通小碎片普遍升为山体。
- 分类同时保留真实面轮廓、多面区域的各个部分及孔洞；不能只画中心、任意截断延伸或丢掉预算外的部分。

## 2. 连续山岭、纹理与等高线

- 大华岭及技木附近属于同一主山岭的内部林地、荒原面，共用连续山脊高度场。不能按每个用地面独立从零高度起山，形成叠在主山上的山包和内圈坡脚。
- 共享区域沿用一致的坡面法线、高度归一化、坡脚尺度和等高线间隔，内部边界平滑衔接；同时保留林地、荒原等材质差异。
- 只对符合真实几何关系的山体共享高度场，不能仅凭包围盒重叠合并。真实孔洞中的独立山体、分离山体和已标注峰点必须保留。
- 等高线、坡面明暗、山脊和河谷来自同一个连续高度场，集成于现有山体材质。等高线必须反映坡面起伏，不能只在大面中央放几个装饰圆圈。
- 保持克制的颜色、林地纹理和深浅层次，不恢复过亮的山体、规则同心圆、阶梯挤出或额外叠加的透视山体层。俯视保留现有贴地材质；用户于 2026-10-12 要求透视结合已有等高线，倾斜视角改用同一材质网格的高程构造贴地表面，等高线、纹理、道路、水体和模型共用该表面。复用原材质位置与图层 ID，不另起独立山体；不夸大海拔，不改变已确认的高程、河谷及分类算法。
- 地形关闭后，基础森林树冠纹理仍显示，可隐藏等高线和地形专用标注；不能把所有森林纹理都绑定到地形开关。
- 分类遮罩保留准确像素归属与透明度，不能混合归属 ID 产生白缝，也不能用共用并集遮罩造成越界块状叠画。
- 推断高度与纹理属于制图表达，不冒充实测 DEM；存在有效高度或峰点参数时保留其约束。
- 山地高度场纳入所有有效 `ele` 峰点、垭口及其他高程点，不能再按前八个峰点截断，也不能把真实海拔限制到 2500 米。零米是有效高程；无效文本、缺失值与不合理数值不作为约束。已标注点在共享高度函数和实际材质网格中保留对应海拔，河谷、边缘过渡和内部用地面不能再次把它压低。
- 高程约束、坡面法线及等高线使用同一场；峰点和垭口直接参与网格细分。数据稀疏处保留推断坡面，森林公园、普通小林地及明确平原排除规则优先。本阶段暂不生成平地高度起伏；后续三小时完整重建自动采纳新增、修改及删除的山区高程，不要求逐山手动补点。

## 3. 山上的水体、道路、建筑和园林

- 山体不能被普通用地盖住；山上的水体、河流、道路、建筑、园林及既有模型要素必须在山体上可见，不能被地形遮盖。
- 快照提前包含相关水体、完整河流、建筑和园林范围。首次绘制就使用这些要素，不能等拖拽或放大后才补遮罩，造成河流、花园迟到或地形闪变。
- 河流及湖岸约束同一个高度场，体现沿河谷地与周边坡面；运河、排水沟、园林池塘不能被当作深切自然山谷。
- 面状自然水体的完整内部也参与河谷约束，不能只压低岸线而使宽河、湖泊中间鼓成山脊；真实岛屿孔洞保持陆地。此约束与已有高程点共同用于同一坡面，不把数据稀疏处的推断坡面宣称为实测水面或水动力模拟。
- 遮罩尊重真实轮廓与孔洞，不能遮掉无关坡面或越出园林边界；水体关系须保留完整几何，不能只使用被当前视野裁断的一段。
- 梅岭、桃林等位于已识别山体内部的园林沿用所在山体的连续高度场、坡面明暗与等高线间隔；园林地物保留自身颜色、纹理和标注，不能挖成零高度透明槽，也不能在母山上另起山包。仅按真实几何包含关系衔接，不将普通园林或森林公园普遍转成山体，真实水体及无关孔洞继续保留。
- 小山按实际尺度处理坡面，近景坐标保留亚米精度，不能出现大山采样带来的方块和粗条带。等高线采用随比例尺保持可读的细线，与园林共享同一个坡面场，不能仅描绘用地外轮廓；道路、建筑与水体的真实轮廓保持可见，不凭步道或景点名称虚构实测高度。
- 园林底色参与坡面材质融合；种植纹理、园林边线及步道在坡面材质之后绘制，立体模型继续共用深度遮挡，不能为了恢复山体明暗而压掉园林细节。
- 明确 `leisure=garden` 与 `landuse=flowerbed` 的花园、花坛在近景增加花簇、矮灌木及少量观赏树模型；花坛只加花簇，点状花园保持紧凑，名称带“花园”不能把普通建筑或公园变成花园。模型保留真实面边界、多面部分与孔洞，避让已加载的道路、水体、建筑、亭子及明确树木；山上园林仍沿用已有贴地连续坡面，高架花园保留标注高度，不新增虚构的地形、园路、水池或建筑。近景模型共用深度遮挡，日夜分别配色，地形开关不决定花园模型是否显示。
- 花园模型按原始要素及固定网格确定位置，不能在缩放、拖拽时重新随机。复用现有近景底图请求及后台模型 Worker，地表先显示、植被后台补齐；面状花园与花坛适度缩小布点间距，单片最多 320 组植被、单园最多 160 组，按范围大小分配，不能因同片小花园数量多而漏掉较大的园林。点状花园继续只显示一组紧凑花簇。远景保留轻量种植材质，减少重复图标。花园持久缓存沿用现有模型缓存的三小时年龄、总数量与容量预算，使用独立算法版本，密度变化正确失效旧花园模型，不能因增加花园而清空仍有效的建筑和结构物缓存。花瓣精度仅用于有限花园模型，不增加道路及用地的索引成本。新建筑、亭子数据到达后重新应用花园避让，不重复叠画同一要素，也不因此重复上传地表及重建山体。

## 4. 预加载、性能与定时更新

- 保留完整发布快照、空间分包、预制概览材质、近景细化和离线兜底，资产遵守 Cloudflare Pages 单文件 25 MiB 限制。
- 首次先显示已有完整概览；缩放、拖拽期间保留已加载山体，后台补齐和细化，不能先清空再重新等待。缩小不能导致整片山体消失或从头加载。
- 当前区域原始分包未全部加载时，不能创建空白或不完整的细化网格接管概览；同代区域数据完整后才接管，真正完成的空区域仍可清除旧山体，不能把“没下载”当成“没有山”。
- 复用解析后的数据、已完成材质、GPU 网格和持久缓存；解压、解析和网格计算尽量在后台 Worker 完成，拖拽期间延后昂贵细化。预制材质与近景结果按范围接管，不能重复叠画变暗。
- 建筑、亭子和墙体的解析与几何生成在后台完成，保存已处理的三小时浏览器缓存；缓存年龄不能在读取时重置，模型分类、尺寸、颜色或几何算法变化时自动失效。缓存启动缓慢或不可用时继续网络加载。中远景减少细碎请求，近景保留完整模型细节；拖拽期间只接收缓存结果，停止交互后再提交模型和切换快照所有权。继续保持完整建筑快照接管和去重，不用半包覆盖已显示的完整模型。
- 已访问的建筑与结构物区域继续保存，移开再返回优先复用已处理几何。内存缓存分别最多 256 块，按最近使用及几何估算容量淘汰；建筑 48 MiB、结构物 16 MiB，当前可见和仍在显示源中的必要模型优先保留。浏览器持久缓存合计最多 1024 块及 256 MiB 几何估算量，旧缓存升级时迁移，不能随意清空；读取及内存命中仅限频更新轻量访问记录，不重写整个模型或延长三小时有效期。
- 显示源保留视野周围已经访问的相邻分块，在覆盖范围和数据版本没有变化时不重新合并或提交 `setData`。邻近额外模型同时受分块数量及容量限制，不能把所有历史区域一直放入绘制源；远区域返回允许从缓存重新提交显示数据。完整新区域才能替换已显示的完整快照，失败和不完整请求继续保旧，刷新后的几何必须正确接管，缓存不能压掉新数据。
- 缓存启动或读取超过短暂等待窗口时允许网络并行加载；迟到但仍有效的缓存若先于网络返回，继续复用并取消多余请求，不能因一次读取稍慢就丢弃已保存模型。缓存未命中、不可用或一直没有响应时，网络加载仍能独立完成。
- 图层位置、模型过滤与可见性未变化时不重复提交样式；修复新加入图层的遮挡顺序，同时避免每次数据到达时来回调整相同图层。
- 地形绘制可以跳过完全位于视野外的连续三角形批次，但不能修改原始顶点、顺序、高程、轮廓或遮罩，也不能丢掉跨越视野的三角形。已缓存完整网格继续保留，旧版无索引材质仍可显示；俯视和透视分别跟踪实际控制器的拖拽、缩放结束，不能把逐帧同步相机的事件当成交互结束。
- 透视地表按现有完整网格在后台转换为配对高程和材质瓦片，复用发布概览并按完整近景网格接管，不因相机移动重新推断山体。高程保留原网格的连续边缘过渡；水体、建筑和园林的材质孔洞不压低下面的地表。转换使用三角形空间索引、取消过期排队请求；配对瓦片内存最多 64 块及 16 MiB，持久缓存最多 96 块及 32 MiB，按算法、输入网格和配色失效。新发布代不能叠上旧代的近景高程；首次转换失败恢复原有俯视材质，不能拿虚假的零高程代替未加载山体。恢复俯视时保留原 GPU 网格和后台缓存，模拟卫星始终不启用这份倾斜地表。
- 透视接管前预热同版高程和材质，准备期间保留完整旧材质；更新失败继续显示上一份完整地表。完整细化单元接管自己的整个范围（含坡脚），不能残留粗网格高点造成锯齿尖刺；真正完整的空单元允许清除旧地形。后台仅处理瓦片相交的三角形、地表与地物，并跳过已被完整细化单元覆盖的概览。网格按需传给后台，旧请求仍使用其原版网格；历史引用按容量淘汰，当前与显示中的完整版本保留，不因拖动反复复制所有已访问地区。
- 修改几何、高度场、河流、遮罩或材质算法后正确失效相关缓存；前端、后台 Worker 和快照构建使用一致算法。
- 交通和地形数据继续由 [.github/workflows/data-refresh.yml](../.github/workflows/data-refresh.yml) 每三小时重建与校验，页面每五分钟检查发布的新版本。数据构建、提交和部署不依赖 Codex 定时聊天；Codex 健康巡检只负责检查与异常提示。
- 完整校验后才原子替换地形、上下文、分包和材质；请求、构建或新资产失败时，保留上一代完整可用快照，不混用新旧代际。用户重新打开页面可复用缓存，并继续检查新版。
- 保留人工服务和显示规则，自动更新不能覆盖 `site/transit-services.json`。数据抓取不完整时停止替换，不能伪造成功。
- 交通显示按数据代际复用已经准备的车站集合、来源 ID 索引和空间索引；同代数据在覆盖范围内移动、关开交通或刷新失败时不能重新生成全部站点和绘制对象。正式关系元数据、人工规则、新站和新铁路基础设施到达后正确更新缓存，不能让缓存压掉更新。实时铁路与公交几何收集使用后台 Worker，与三小时快照构建共用同一收集算法；后台失败保留现有交通显示，不清空后等待重建。透视只生成所需矢量交通对象，不能再同时生成不可见的俯视标记；标签碰撞先批量读取位置再调整，避免逐站触发布局。
- 已加载铁路包不再因每次移动触发强制重绘。俯视交通按变化增量接管，复用未变化的线路几何、站点符号和标签；新数据中几何及外观未变化时同样保留绘制对象，点击读取最新完整站点详情。缓存随交通筛选、站点选择、坐标、颜色及数据规则变化正确更新；仅保留当前显示范围的对象，不无限积累历史标记。拖拽与缩放期间保留现有完整交通显示，结束后再提交待更新数据；标签碰撞用空间网格筛选，只改变可见性，不反复拆装标签。线路拼接仅对最终选中的连接复制几何，保留既有端点顺序、距离门槛、方向判定和导航结果。
- `generatedAt` 反映原始数据生成时间；仅重新计算材质使用相应准备时间，不能假装重新抓取过 OGF。
- 仅修正共享高度场或材质算法时，可运行 `node scripts/rebuild-terrain-material.mjs` 用当前完整快照和地物上下文重建，不重新抓取高程。候选完整校验后原子接管，旧资产保存在本地重建目录；三小时工作流仍使用同一共享算法。
- 工作流成功、GitHub 已提交与 Cloudflare 已部署分别核实；缺少部署凭据而跳过部署不能报告为生产数据已更新。

## 7. 交互、标签与既有结构物

- 华域模拟卫星是根据 OGF 地物生成的可选底图，菜单与署名明确标注模拟性质，不冒充实拍卫星影像，也不使用与虚构地理错位的真实地球影像。沿用现有数据源、要素轮廓、分类和标签锚点，以平面屋顶、树冠及自然地表材质表达俯拍效果；不显示建筑侧壁、亭子柱子、地台、树干、站棚支柱和立体花簇，禁止继承或开启倾斜相机。屋顶、树冠共用现有快照源，跟随完整快照接管时的可见性与去重过滤，不另抓取或复制几何数据；异步模型到达后也不能恢复三维显示。屋顶颜色继续尊重有效标签，建筑填充不能假平移。交通和地形仍可分别勾选，共享三小时快照与模型缓存，不另生成一份全图数据，也不新增独立透视山体层。切回标准或深夜底图恢复各自原有模型、高度、中空结构和样式，选择沿用现有持久化设置。
- 模拟卫星默认隐藏普通地名与制图图标，允许通过“影像注记”独立恢复原锚点的地名；保存该偏好，并在晚到的标签中继续应用，显式启用的交通标注不受影响。隐藏行政边界、公园制图边线和地下线路，道路采用自然路面材质和弱描边。地表材质为固定、多尺度的连续纹理，缩放、平移和重开不重新随机；共用样式图片缓存，不逐帧生成。屋顶、树冠投影是轻量平面材质表达，共用原几何与过滤，绘制在屋顶和树冠下方，不位移实际屋顶、不新增立体模型或虚构道路、建筑、地块边界。明确颜色标签仍优先；投影和材质不能冒充实测影像或光照数据。
- 切换底图时清理旧地形材质的后台 Worker、定时回调、监听及 GPU 资源；异步结果不得访问已移除地图或改写新底图的诊断状态，已处理的共享数据缓存继续保留。
- 交通与地形是独立勾选功能，可以同时启用或同时关闭；交通视图继续允许选择显示的交通要素。
- 切换到其他功能时显示对应面板，不能残留导航页面；保留地点选择开关及既有相机状态规则。
- 行政区下载可独立选择是否包含行政中心点；默认包含。关闭后图片不绘制中心符号、地名注记或点图例，也不能在区域中央补画行政区名称代替点注记；SHP 不附中心点图层，OSM 不附中心节点但保留组成边界所必需的几何节点，不再等待中心补查或把主动排除报告为中心缺失。行政区边界及矢量名称属性保留，图片标题、坐标信息和来源说明保留；OGF 栅格底图自带标注不受此开关影响，界面明确说明。
- 下载图片可选择长边 1200、2400（默认）或 4800 像素，预先显示输出尺寸；PNG、JPG、TIF 和矢量 ZIP 内附底图均实际使用所选尺寸，不改变地理范围。边界与文字按尺寸直接绘制；底图选择相应原生瓦片细节并限制并发及请求总量，TIF 像元大小和配准锚点随实际尺寸同步调整。纯矢量下载禁用图片分辨率，保留用户已选值。
- 行政名称锚定真实行政几何或标签位置；上京都等名称不能跟随视图中心漂移，不能被标到无关山地。
- 行政区、下级区划、地点轮廓、道路及下载范围的高亮跟随当前实际相机缩放和平移。透视时使用底图同一相机绘制原始地理几何，隐藏旧俯视画布，不能把冻结的轮廓叠在移动的底图上；恢复俯视后同步路径与画布变换。侧栏开关、晚到的选区及底图切换继承此规则；相机移动不重新抓取或提交整份边界，不改变真实边界、导航及地形。
- 透视恢复俯视时，底图必须明确接回俯视相机的中心、比例和方向；即使连续缩放四舍五入后与保留视图相同、地图未触发移动事件，也不能留下两个控制器比例不同的状态。
- 标准及深夜底图分别表达地市级（`admin_level=5`）、区县级（6）和更低层级边界，地市界不能混成乡镇灰线；放大后仍保留国家、道、省等上级边界。模拟卫星隐藏边界的规则仅作用于其自身样式，切回其他底图后恢复。
- 交通画布在缩放结束、窗口调整及新显示对象接管后，按同一地图视图重投影现有路径，保留站点与线路对齐；不能因视窗缓存而跳过用户明确触发的刷新，也不能为修正显示改变导航坐标、线路关系或站内换乘。
- 亭子模型仅用于明确类型标签的点、面及多面关系：`building`、`building:part` 或 `man_made` 为 `pavilion/gazebo`，`leisure=gazebo`，或 `amenity=shelter` 且 `shelter_type=pavilion/gazebo/picnic_shelter`。名称含“亭”或以“亭”结尾不能作为识别依据，普通建筑、景点和未注明类型的遮蔽物保持其原有分类；公交候车亭继续单独处理。前端分类、结构物查询、缓存和数据刷新均遵守这条规则。
- 亭子高度优先读取有效参数，否则使用既有默认值。面状亭子匹配原始面范围；点状亭子按可用空间调整大小并避让道路。
- 保留亭子中空结构、薄底板、内收边柱和自适应中心柱，柱子不能跑出屋顶；不能回退为不通透的实心块。
- 建筑模型使用有效颜色标签，优先级为 `building:colour`、`building:color`、`colour`、`color`；支持 CSS 颜色名、十六进制及 RGB/HSL 颜色，六位无井号色值补井号。屋顶专用 `roof:colour/roof:color` 优先用于已建模的独立屋顶，不改变墙面颜色。缺失或无效值逐级回退到现有普通建筑、古建筑和亭子配色；保持模型高度、实心遮挡、亭子中空结构和地台材质。点、面、关系及建筑部件经过快照接管、实时更新和日夜切换后同样遵守该规则，不为颜色另加图层。
- 保留墙壁、栅栏、建筑和巴士站等已有显示。结构物与建筑快照完整接管，避免重复叠层；同一墙体不能同时重复绘制平面和立体表现。
- 体育场等要素保留中心优先、逐块显示的加载方式，不因地形改动退回等待整片完成。
- 模型、体育场跑道和场地细节只等待所需样式定义及自身数据，不等待所有底图瓦片、字体或其他资源加载完；异步到达后立即恢复对应图层的显示，稳定可见性不重复提交。
- 透视中地面道路、河流、场地与贴地山体材质先于立体模型绘制；道路不能穿到树冠、建筑或亭子屋顶上。树木、建筑、墙、亭子、站棚及抬高的绿地共用真实深度遮挡，按位置与高度相互遮挡，实体表面不透出后方模型。标签和交通站点符号继续作为地图标注显示。
- 保留模型实际高度、底部高度与中空几何，不把亭子填实、不把屋顶绿地压到地面；保留道路桥梁和隧道的既有相对顺序。异步快照接管、新图层加入、透视与俯视切换后同样应用遮挡规则，无须等待所有数据加载完。
