# 品牌与地铁 logo

发布构建：`9.0-brand-management-v1`（2026-11-18），包含此前本地 `9.0-brand-logos-v2` 的标识加载与命名修复。线上版本以实际发布结果为准。

## 已接入的标识与地图显示

用户指定的 [OGF 商号索引](https://palewod.github.io/ogf-brand-index/) 的 `data/logos.json` 当前提供 aniM、ToDays、高全达通和高阳银行四个文件。原件、来源更新时间及 SHA-256 保存在 `site/brand-logos.json` 和 [图像来源](../site/brand-logos/ATTRIBUTION.md)。图像版权归各权利人，不能因地图数据采用 ODbL 就认定 logo 也采用同一许可。

“品牌 → 品牌与地铁 logo · 共享标识”中可查看、筛选标识，并开关地图 logo。原生 z14（地址栏约15级）起读取当前缓冲近景，显示 logo、实际名称及分店；密集处按比例尺避让。无需先打开某个品牌的分布图。商业点、线或面都保留原始 ID；线面中心只用于标注，不冒充入口。

- 名称采用 `brand · branch`，例如 `aniM · 津川站前店`；即使 name 已含完整分店名也只组合品牌和分店一次。缺少 brand 时使用已确认匹配的品牌名；没有 branch 时保留实际名称。地铁保留站名。地图和分店列表共用此规则，旧缓存按原标签重新格式化，不改变源时间。
- 优先匹配原始 `brand` 或明确语言标签，显式其他品牌不会被店名覆盖。
- 缺少 `brand` 时，仅在商业设施中按完整名称、分店后缀和明确别名识别；已知分类须兼容，银行与 ATM 可兼容。
- 普通建筑、公交站名、无关同名地点和冲突不强行归属。只在对应附近的 logo 成功准备后替换通用符号。
- 地铁／轻轨／单轨／电车标识使用明确 `network`、`operator`、语言名或正式线路成员，不能按站名猜系统。交通总览复用现有站体，不新增或改移站点，不改线路颜色、换乘、去重与导航；多系统冲突保留原图标。
- 俯视与倾斜共用身份，模拟卫星遵守“影像注记”。点击可打开真实物体详情，测量、范围和导航选点仍优先。

## 上传、更新与删除

1. 登录地图账号，在品牌页展开共享标识，或在某个品牌详情中点击上传入口。
2. 选择品牌、运营者或地铁系统，填写与地图标签一致的完整名称。明确简称、语言名用分号列在别名栏，不用其他品牌名作别名。
3. 选择 PNG、JPG、WebP 或独立 SVG（最多8 MiB）；本机等比缩放到128×128透明画布，保留原图背景，不自动抠图。预览后填写来源说明，可选 HTTPS 来源链接。
4. 确认具备公开使用权，点击“公开共享 logo”后才上传。仅公开转换后的小图，不上传本机其他文件。

同类型及归一化名称只保留一份共享标识。普通用户更新或删除自己的 logo，获批品牌管理者可维护对应品牌 logo，管理员可维护全部且保留原作者；其他用户不能覆盖共享记录。管理员按品牌禁止某用户后，该用户即使是原作者也不能继续上传、更新或删除此品牌 logo。申请流程见[品牌管理说明](BRAND_MANAGEMENT_ZH.md)。内置 logo 可由共享新版替换，删除新版会恢复内置；无内置时恢复原地图符号。保存有版本检查，冲突须刷新后重试。退出或换账号清理草稿与权限，删除账号同时删除其 logo。

SVG 拒绝脚本、外部资源及不支持内容。服务端只接受重新验证的 PNG，检查签名、尺寸、压缩长度与块校验，去除附加内容；数据库不保存原始 SVG。输入／保存失败保留已有公开 logo。

## 更新与性能

开启地图 logo 时，共享目录和当前近景地点每两分钟检查一次，后台暂停；作者成功保存后本页立即检查，其他用户在下一次检查或手动刷新时读取。仅查询当前缓冲视窗，移动和样式就绪通知复用同一范围的在途请求，不取消后重新发起；每种 logo 只解码一次，所有对应地点共享同一地图纹理。读取保留源时间，不因缓存命中冒充新抓取。临时连接失败或限流在服务端最多额外重试两次，短查询可在同一官方端点改用 GET，永久拒绝、损坏或计数不完整不重试成成功；相同查询共享在途任务，取消某个页面不影响其他读取者。失败保留三小时内的同范围完整结果，限频后再检查。浏览器在当前标签页最多保存8个完整窗口、合计2 MiB、三小时失效，重开本页先恢复同一标识目录和覆盖范围的完整缓存，按原始读取时间决定更新；存储被拒绝仍可使用。首次临时失败可再自动重试两次，“刷新 logo”同时重读目录与当前地点；后台、关闭和离页取消待重试任务。

单次最多1000个已登记标识、3000个源对象、8 MiB响应及每轴0.8度的近景范围，超限或上游不完整时明确提示并保留原符号／已显示完整结果。此边界不改变共享 CSV／GeoJSON 数据包的无应用配额规则。

本期内置文件取自上述源目录的2026-10-27版本；共享上传可更新内置图像，本期不声称已自动同步上游未来新增文件。原品牌目录三小时重建、两分钟建模和五分钟快照检查保持原规则。助手可打开品牌管理入口，图片仍由用户选择和核对发布。

## 维护与接口

幂等迁移 `migrations/0005_brand_logos.sql` 和 `migrations/0006_brand_management.sql` 复用既有 D1，部署前按顺序应用。无 D1／迁移不可用时公开内置标识继续可读，上传明确失败，不影响地图其他接口。

| 接口 | 用途 |
| --- | --- |
| GET /api/brand-logos | 合并内置与共享元数据，公开读取 |
| POST /api/brand-logos | 已登录用户新建共享 logo |
| PATCH /api/brand-logos/:id | 作者／对应品牌管理者／管理员更新，须 revision |
| DELETE /api/brand-logos/:id | 作者／对应品牌管理者／管理员删除，须 revision |
| GET /api/brand-logos/:id/image?v=hash | 公开版本化 PNG |
| GET /api/brand-logo-places?bounds=W,S,E,N | 当前近景的完整匹配地点及源时间 |

算法维护在 `site/brand-logo-core.js`，接口在 `site/brand-logo-server.js`。运行 `npm run logos:sync` 同步独立 Worker，`npm run test:brand-logos` 验证匹配、图片及权限。整包 `npm run verify` 包含该检查。地图助手合同变化还需 `node scripts/sync-map-agent.mjs`。发布前继续运行仓库规定的全部校验，GitHub 提交与 Cloudflare 部署分别核验。
