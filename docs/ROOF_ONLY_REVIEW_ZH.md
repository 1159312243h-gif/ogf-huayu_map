# 抬高的独立屋面修复

验收版本：`7.5-roof-only-v1`，2026-10-25。本地验收时尚未上传；2026-10-26 按用户“上传”要求纳入发布，实际提交及部署状态以 GitHub Actions 和线上检查为准。

用户截图标签为 `building=yes`、`height=4.5`、`min_height=4`、`roof:height=0.5`、`roof:shape=skillion`、`roof:direction=270`、`roof:colour=#575757`。原实现将底高压到 3.9 米、总高抬至 4.7 米，并强制为屋顶保留 0.6 米墙高；单坡网格另补三边侧墙，导致本应只有屋面的结构出现墙体。

现在保留有效底高 4 米及总高 4.5 米，屋面低边为 4 米、高边为 4.5 米，并按 270° 向西下降。当屋顶高度占满有效总高与底高之差时，仅生成屋面，省略侧墙、山墙和水平底板；折坡中的必要连接面仍保留。只有实际生成完整屋面的对象才排除其原生挤出盖板，失败、预算不足、俯视及卫星回退完整原表达。有实际剩余墙高的普通建筑继续保留墙体，亭子不改变。

阴影从同一屋面三角形生成，不补水平底板或墙体投影。后台模型 Worker 直接序列化相同解析函数，并以函数指纹失效旧的已处理模型；Cloudflare 建筑缓存策略升级至 `huayu-building-v8-roof-only`。阴影及屋面脚本使用同一新版本。没有重抓或改写源数据时间，也没有重建地形快照或清空无关缓存。

已验证用户标签的高度、两片屋面及零侧墙、真实剩余 0.2 米墙体、19 种屋顶、后台／前端一致、原生过滤的对象身份及回退、实际 GPU 几何和阴影。真实 Chrome / MapLibre 以相同标签及合成矩形轮廓渲染对照，确认仅屋面对象不再绘制原生盖板，而普通建筑保留墙体；关闭模型恢复盖板，重新开启正确接管，无地图或页面脚本异常。截图位于 `.data-update/roof-only-fixed.png`，此对照不冒充已定位到截图中的原始建筑。
