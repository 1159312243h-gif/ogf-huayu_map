# 地图助手接口

本次发布构建为 **9.0-transit-templates-v1**。用户可在“助手 → AI 接口设置”配置自己的服务商；没有自备或站点接口时不能进行模型对话。上传和部署状态另行核实。

## 用户自行配置 AI

1. 选择服务商预设，或选“自定义接口”填写 API 地址。
2. 选择接口协议，填写服务商提供的准确模型 ID 和 API 密钥。
3. 点击“应用配置”开始使用，或点“测试连接与工具调用”。测试发送一条简短的合成请求，要求模型调用能力查询，不发送当前聊天、附件或地图资料，也不执行地图工具；会产生所选服务商的实际用量。
4. 测试成功后可用对话查询和准备草稿。仅有文本回复而没有完成工具调用的接口会提示测试未通过。服务商地址、区域和具体模型是否可用，须以实际连接结果为准。

| 服务类型 | 协议与预设 |
| --- | --- |
| OpenAI、DeepSeek、通义千问、Kimi、智谱及兼容网关 | OpenAI Chat Completions，支持自定义 API 根路径，也兼容填写完整 /chat/completions 地址 |
| Anthropic / Claude | 原生 Messages，兼容 API 根路径或完整 /messages 地址 |
| Google / Gemini | 原生 GenerateContent，填写 API 根路径及模型 ID，密钥通过请求头发送 |

自备接口的公开查询和对话不要求地图账号；准备公开投稿或上传文件继续由原表单要求登录。可选站点接口仍沿用管理员设定的登录要求，不会把站点密钥用于用户填入的地址。接口只接受公开域名的 HTTPS 443 服务，不接受本机、内网、IP 字面量或带凭据／查询参数的地址；不跟随重定向，请直接填最终接口。模型不能修改连接设置或选择其他地址。

**API 密钥只保留在当前页面内存与密码输入框**，随请求经本站 Worker 转发到用户填写的服务商；不存入账号、D1、localStorage、sessionStorage、共享资料或日志，不放在 URL 或模型消息里。刷新、页面离开、退出或切换账号均清除密钥，需重新输入。“记住”只保存当前账号在此浏览器的服务商、协议、地址和模型，不同步其他设备；游客使用独立设置。更换配置清空本轮对话，取消旧请求及旧地点引用，迟到结果不能再操作地图。清除对话可保留当前连接，另有按钮清除接口配置和密钥。

OpenAI 兼容服务的工具历史保留必要的 reasoning_content，Gemini 工具历史保留不透明 thoughtSignature；这些仅用于协议往返，不作为系统指令或公开信息。所有模型输出都要经过相同的工具名、参数和权限检查。兼容层及浏览器流程已使用模拟服务验证，未替用户配置或调用真实付费模型，不能据此承诺每个服务商／模型均已实际联调。

## 已接入的地图工具

- get_capabilities：读取本版本可用功能及限制。
- get_map_context：当前实际相机视窗、选中公开物体的类型／编号及真实地点引用；不读取私人收藏。
- search_places、locate_place：复用 OGF 地名、坐标与设施检索，最多返回 8 条，保留真实引用；同名先选择。
- prepare_navigation：把两个真实引用填入既有导航及出行方式，在原页面开始规划，未计算不能说已有路线。
- search_shared_info、search_datasets：公开投稿、补充名称属性及数据目录，保留来源、日期和分页范围。
- open_dataset：打开完整共享包，在原页面统计、制图和下载。
- prepare_feature_info：为当前确定的 OGF 物体填写简介、来源和属性；登录后准备，原表单核对后发布。
- prepare_dataset：把主动选择的 CSV／JSON／GeoJSON 附件带入数据表单并在本机校验；原文不自动送模型，不自动公开。
- get_brand_profile：查询共享品牌公开简介、官网和管理者，不向模型返回私人申请说明、依据或审核记录。
- prepare_brand_management：登录后为指定完整品牌名准备申请说明和可选依据链接，复用原表单并保护已有草稿；只准备、不提交，不能审批或禁用。首位申请通常自动通过，后续同品牌申请待管理员审核。
- open_panel：打开品牌、线路、模拟、测量、收藏、贴图、下载、渲染、账号及帮助等现有入口。品牌页包括共享品牌／地铁 logo 管理，图片由用户主动选择并在原表单核对发布，助手不自动读取或发布本机图片。打开入口不等于执行页面内全部操作，后续按需求增加具体工具。

没有直接修改 OGF、删除别人投稿、替换交通计算或后台执行任意脚本的工具。原表单草稿、作者／管理员权限、数据完整性和地图规则继续生效。

## 服务端接口及可选站点服务

GET /api/agent/status 公开返回可用协议及站点服务状态，不返回凭据。POST /api/agent/chat 接收 messages 及可选 connection（protocol、baseUrl、model、apiKey）。自备 connection 每次独立校验，不能缺少自己的密钥而回退使用站点密钥。POST /api/agent/test 使用相同连接适配，只返回连接与工具调用测试结果。写入仍使用原共享 API 的身份校验。

可选站点服务沿用以下 Cloudflare 服务端变量；未配置时用户仍能自备接口：

| 变量 | 含义 |
| --- | --- |
| MAP_AGENT_API_KEY | 站点模型 API 密钥，设为加密 secret |
| MAP_AGENT_MODEL | 实际获授权且支持工具调用的模型 ID |
| MAP_AGENT_BASE_URL | HTTPS API 根地址，默认 https://api.openai.com/v1 |
| MAP_AGENT_PROTOCOL | openai（默认）、anthropic 或 gemini |
| MAP_AGENT_ALLOW_GUESTS | 站点服务默认需登录，显式 true 才允许游客使用 |

状态、错误和测试结果不返回服务商原始错误体。密钥、密码与 Cookie 不进入公开日志或模型消息；查询与投稿按不可信资料处理，界面只显示安全文字。聊天只保留本页内存。对话最多40条协议消息、请求最多256 KiB、模型响应最多1 MiB、45秒超时；每轮至多6次模型往返。这些边界不改变共享数据包上传规则。

## 新功能必须同步

1. 在 site/map-agent-contract.js 维护功能名、输入 schema、作用范围和真实限制。
2. 在 site/map-agent-tools.js 复用现有模块处理器，不能另实现地图业务算法。
3. 需要公开写入的功能先准备原表单草稿，保留作者和管理员权限。
4. 模型协议适配维护在 site/map-agent-providers.js；运行 node scripts/sync-map-agent.mjs 同步独立 Worker，再运行 node scripts/test-map-agent.mjs。
5. 同步站内帮助、本说明和 README；新增菜单遗漏或前后端漂移须使检查失败。发布前继续执行既有整包及数据检查。

新参数化功能必须补充真实处理器和结果测试，不能只修改提示词宣称支持。

品牌与分店显示名采用“brand · branch”；没有分店标签保留实际名称，地铁保留站名。地图标注及品牌列表由共享算法实际格式化，助手不另行编造分店名。

品牌 logo 的自动加载与恢复由品牌模块实际执行：助手仍可打开共享标识入口；入口内“刷新 logo”重读目录及当前地点，失败保留同范围完整缓存与原始源时间。不宣称已联网读到门店或已绘制图标，除非对应读取和显示确已完成。

## 本地新增：线路显示模板

- get_transit_templates：读取实际公交纸质／灯箱／杆挂／LCD／LED／电子墨水站牌及车载路牌／地铁导视／LED／LCD 模板目录和当前真实线路摘要。外部城市参考不等于内置同款。
- prepare_transit_template：使用目录返回的真实编号和 selected／demo 来源，打开原线路工作区进行预览。selected 须已选中且读到站序；demo 明确标注演示。只准备显示图，不下载、不共享、不发布，不代表实时到站。

模板导入、PNG／SVG 及统一清单、共享发布由原界面实际处理。共享复用数据页及其作者／管理员权限，原表单确认后发布；助手不会把模板中的文字当指令。详见 [线路模板说明](TRANSIT_TEMPLATES_ZH.md)。

公交站牌的实际目录包含 busLayout，不只给出颜色。prepare_transit_template 仍由原处理器选择真实编号，公交初始选中一个已读位置，仅作预览；用户可在原界面调整本站。只展示当前线路及已有原始服务标签，不编造全站线路、到站分钟数或另一方向时刻表。

同站多线路：get_transit_templates 另返回 selectedStation（真实站点编号、已收录线路／方向数及 complete 由当前整站查询／自选状态决定）。prepare_transit_template 可选 display=line／station；station 只用公交模板，selected 须已有自动查询或用户逐条收录的本站牌，demo 为三线示例。prepare_transit_template 处理器实际预览已有整站图；新增 load_transit_station_template 可按当前选站或真实地点 ref 查询本站全部已登记公交关系，不推断对向站，也不把“打开入口”等同于抓取完成。

模板目录已扩充为 53 套，其中公交 26 种结构，新增 compact／split／wide／cards／hub／bilingual。get_transit_templates 返回真实 busLayout；prepare_transit_template 复用原预览处理器，支持新增样式的单线路与已有同站清单，不额外抓取、生成英文或模拟实时到站。

load_transit_station_template 复用原 UI 的完整查询、取消和原子替换处理器，返回 stationId、lineCount、complete、scope 及原始 sourceTime。complete 只指所选站点已登记直接停靠关系已读完，不包含未登记线路。prepare_transit_template 仍只预览已有数据；助手不会编造运营时间、票价或替用户补填。公交横向自动排版，不再显示公交互换文字；跨方式提示、原始服务资料及本页人工补填由真实界面执行。

公交模板处理器已同步精简图片、循环线回接及运营资料继承。load_transit_station_template 返回运营方补查状态 operatorStatus；get_transit_templates 返回的限制说明包括发车时刻与间隔分列、缺项及冲突不猜。仍复用真实查询及预览处理器，不让模型编造公司安排或到站时间。

所有模板和原线路导视共用无虚构首站及真实资料规则；多线路预览使用分隔线。助手继续调用原渲染器，不把成员排列的第一个站点解释成运营首站，不在图片额外添加环线或循环接首站文字。

环线终点不再隐藏：真实处理器保留明确的 from/to，缺项标为未提供，主关系端点只在全部已读直接方向一致时共用；主线与回接线等粗。助手仍走同一渲染器，不替用户指定运营终点。

起终点显示统一以当前线路关系的 from/to 属性为准；普通线路也不按成员站序推算终点，换向预览不互换属性，缺项如实显示。真实模板处理器和导视共用此规则。

新增公交车厢屏：get_transit_templates 的真实目录包含 screenLayout 和 animated，支持 LED 走马灯、上下交错、斜排、折返、闭合回接及邻站放大。prepare_transit_template 通过真实模板编号调用原 UI，返回 screenLayout、animated、realtime=false；不把动画解释为车辆实时到站，不自动下载或发布。新旧共 53 套，PNG／SVG 仍导出完整静态图；用户可在原界面暂停、调速及指定当前站。


## 缺失资料模拟补全与已读线路选择（2026-11-19）

用户最新要求允许缺失资料尽量随机生成，覆盖此前“缺项只显示未提供”的模板展示限制。线路模板默认开启“缺失资料用模拟数据补全”，可关闭；已有真实服务字段、手动输入及来源优先保留。运行时间、首末班、费用、运营方和缺少的班次参数可补全，精确时刻表保留原形式；到站按设备当前时间、已标注间隔／时刻表及模拟站间时间推演，没有间隔则随机生成。随机结果按本页种子和线路身份稳定生成，切换模板不重新抽取；可点重新生成或按现在时间更新。预览可见时整分钟更新，后台、离屏和收起暂停，正在输入时不重绘表单。

按用户最新要求，生成图片中的运营字段、到站文字及底部不显示“模拟”字样或“含模拟数据／非实时运营信息”说明，适用于页面预览、放大、走马灯、PNG／SVG 和下载清单中的图片。生成字段及到站值仍由原模拟算法产生，页面控件、摘要、下载清单说明及 SVG metadata 保留模拟性质、参考时间、字段清单和推演依据，不将图片精简等同于真实运营数据。编辑框原值与模拟占位分开，不因修改一个字段把全部模拟值存成手填资料；导入共享模板只存版式，模拟值不写入 OGF、导航、公开运营资料、数据库或共享模板。终点 from/to、站点名称、站序、环线和换乘仍按已读真实关系，不随机生成或闭合普通线路。

按站读取成功后，“套用哪条已读线路”可选择其中一个真实方向，再切到车载前后牌、公交车厢或轨道单线模板，不必额外从全局搜索重复读线。失败／取消保留既有清单，切换不混入同名对向站。助手 get_transit_templates 返回 selectedStation.lines、previewOptions；prepare_transit_template 可选 lineSourceId 和 simulateMissing，复用同一真实处理器，不能指定未读或编造关系编号。


同一条线路因站序过长分行时，大号线路编号只在第一行显示一次；整站多线路仍分别保留各线编号，站序编号和方向不变。图片内不印生成内容的模拟字样与底部说明，页面和 SVG 元数据继续保留其来源。真实预览及下载使用同一绘制处理器。
