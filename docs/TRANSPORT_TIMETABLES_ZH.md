# 共享车次、城铁时刻与航班

入口：**数据 → 上传共享数据包**选择“铁路时刻表”“城铁时刻表”或“航班时刻表”。在**导航 → 铁路／城铁车次与航班**查询、翻页、下载和估算缺失时刻。原“车次安排（统计）”继续保存频次等一般指标，不会自动变成运营时刻表。

游客公开查询，登录用户上传；作者管理自己的包，管理员管理全部。原件、标准化记录和停靠点索引同一事务保存，失败全部回滚，删除包或账号级联删除索引。不添加上传数量或容量配额；实际设备、平台和 D1 限制继续适用。当前为本地开发，部署状态另行确认。

## 最小文件

UTF-8 CSV、JSON 记录数组或 GeoJSON；每行一个实际停靠点，一个包可有多个班次。最小只需 station 和 departure；每个班次至少两站，首站至少一个时刻。没有 trip_id 时视为同一班次，编号显示“未命名班次”；不填写 stop_sequence 则按文件原顺序。

示意 CSV（不是实际运营资料）：

~~~csv
trip_id,stop_sequence,station,departure
R101,1,甲站,08:00
R101,2,乙站,08:30
~~~

推荐增加 stop_id（如 node/123、way/456、relation/789）；名字相同的不同站不得混用。机场可用 stop_code 填 IATA／ICAO。仅站名也能查询；导航只使用当前完整已加载候选中可唯一匹配的站名，优先显式原始编号／代码。无法明确定位时仍保存表格，不虚构车站或轨道。站名、编号和开行条件不随机生成。

## 字段

| 字段 | 意义 |
| --- | --- |
| trip_id | 车次／航班编号；一个包内同编号为同一班次 |
| stop_sequence | 从1开始的站序；不能重复 |
| station 或 stop_name | 停靠点名称 |
| stop_id | OGF 原始类型／编号；不能把车站编号与站台编号随意互换 |
| stop_code | 机场明确代码 |
| arrival、departure | 到／发时刻 HH:mm 或 HH:mm:ss；time 可代单一停靠时间 |
| service_date | 仅此开行日 YYYY-MM-DD |
| start_date、end_date | 开行有效日期范围 |
| service_days | 周一至周日用1234567；默认每日 |
| utc_offset | 各站 UTC 偏移，默认 +08:00；跨时区航班逐站填写 |
| route_id | 可选明确方向关系，例如 relation/123；填后只能匹配该关系 |
| vehicle_speed_kmh | 车辆最高速度，铁路默认120、城铁80、航空800 km/h |
| acceleration_mps2、deceleration_mps2 | 加／减速度，铁路默认0.6／0.7、城铁1／1 m/s² |
| lateral_acceleration_mps2 | 无超高资料时的侧向加速度假设，铁路0.65、城铁0.8 m/s² |
| dwell_seconds | 缺少发车时间的中间站停站假设，铁路120、城铁45、航空2400秒 |

同一班次的日期、线路和车辆参数在每行保持一致。日期留空代表无额外日期限制，不使用上传日期冒充有效期；每日与 +08:00 的默认规则在上传界面明示。

HH:mm 在后续停靠点早于前一事件时按跨午夜顺延；也可明确使用24:10、25:30等跨日时刻。星期和日期以首站本地开行日为准，各站到发转换到同一 UTC 时间轴。只有一个停靠时刻时作为该点的事件时间，没有另填到达则到达采用该事件；没有另填中间站发车才加默认停站时间。已填写时刻始终优先，估算不能覆盖它。资料来源、作者、统计日期和上传时间分列。

## 导航匹配

先沿用原导航的真实道路、交通关系、轨道与接驳生成候选，再针对候选行程按停靠点、方向、制式和可选 route_id 查询班次。按指定出发时间（留空为设备现在时间）加上到站、进站、换乘时间，选择未来48小时内能赶上的共享班次；候车计入总时间，后续换乘按新的到达时间继续匹配。同一个班次中的中途停靠点须出现在该段路径的真实站序中，不能仅因两端同名就套用。

共享时刻表优先用于可匹配段，其余段、未开行／已错过／不完整候选、断轨或服务暂不可用时保留原默认方案。不同作者数据不拼成一张新时刻表，选中段保留数据包编号、版本和作者来源。导航时间在设备时区显示，查询表保留每站 UTC 时区。不承诺全球最优时刻表换乘搜索、实时余票、延误、停运或实际运营确认；当前是在原候选路径上匹配班次，未另造全球班次路由网。

## 运行时间估算

可只保留首站时刻，其余时刻待估算。估算调用原有交通和铁路路径查找，明确要求连续真实几何；拒绝推定／规划连接和未绘制联络，不用车站间直线补轨。方向关系已指定则保留该关系限制。同制式匹配，不借另一种交通工具补线。

车辆最高速度与已读轨道限速取较低值；基础设施路径保留原始逐段 maxspeed。曲率来自路径原始转折点的外接圆半径，用侧向加速度限制弯道速度；采用前向加速和后向制动包络，站间起终速度为零，短距离采用三角／梯形速度曲线，中间停站单独计时。缺限速使用已明示的车辆默认上限，估算结果保留 trackUnknown、车辆参数、方法和曲率信息。普通关系路径未保留完整逐段限速时明确作为缺项，不声称已取得所有轨道标定。

这是常加速度及简化弯道模型，没有轨道超高、坡度牵引曲线、信号闭塞、会车、限流和调度冲突，不能当工程级列车运行图。航空仅按已匹配机场的航程、巡航速度及20分钟起降滑行假设估算，不模拟风、空管与机型性能。原来填过的到发时刻不被物理计算改写；补全与已填时刻冲突时提示错误，保留原表。估算留在本页，不自动发布、不改写 OGF、原共享文件或三小时快照。

## 接口与维护

- GET /api/timetables：q、mode=rail/urban/flight、from、to、page（从0）、limit（至多50）；按页查询原班次及来源。
- POST /api/timetables/match：只读匹配，pairs 含 mode、from、to（原始编号／代码／明确名称的键）。每批最多100对、每对100候选，超出标为未读全并保留默认导航，不把部分结果当完整。查询边界不是上传配额。
- 写入、改删继续使用原 /api/datasets 接口。新三类完整校验后才写入 transport_trips、transport_calls，后续迁移不依赖聊天持续运行。
- 迁移：migrations/0007_transport_timetables.sql；既有发布脚本按顺序应用全部幂等迁移。新包发布才建立新索引，原 schedule 统计包不会被猜测转换。
- 同步：node scripts/sync-transport-timetables.mjs、node scripts/sync-shared-dataset-core.mjs、node scripts/sync-map-agent.mjs。
- 回归：npm run test:timetables、npm run test:shared-datasets、npm run test:map-agent 和既有四项发布检查。
- 助手 search_transport_services 调用相同查询，estimate_transport_service 仅接受本页已查询记录，prepare_dataset 接受三类新类型，prepare_navigation 可设置含时区 ISO departureAt；助手不自动发布附件或估算。
